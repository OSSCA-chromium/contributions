Reporting/NEL 저장소가 DB에서 불러온 NEL 정책·Reporting 엔드포인트·엔드포인트 그룹 개수를 기록하던 히스토그램 4개를 제거했습니다. 넷 모두 만료돼 기록되지 않는 상태였고, 코드에는 «조사가 끝나면 이 지표를 지워라»는 TODO가 세 곳 남아 있었습니다(crbug.com/40054414). 2파일 +3/−98.

## 문제 설명

- issue url: https://crbug.com/40054414
- `SQLitePersistentReportingAndNelStore`는 로드가 끝날 때마다 `ReportingAndNEL.NumberOfLoadedNELPolicies`, `…NELPolicies2`, `…ReportingEndpoints2`, `…ReportingEndpointGroups2`를 기록했습니다. 뒤의 세 개에는 «TODO(crbug.com/40054414): Remove this metric once the investigation is done.»가 붙어 있었습니다.
- 만료일은 2023-06-25(앞의 둘)와 2024-09-15(뒤의 둘)입니다. 히스토그램 문서는 만료된 히스토그램의 기록 코드를 죽은 코드로 보고 지우라고 합니다.

## 해결 내용

- 히스토그램 이름 상수 4개와 기록 전용 함수 3개(`RecordNumberOfLoaded*()`), 그 호출 3곳을 지웠습니다.
- 호출부는 `if (load_success) { 기록 } else { DCHECK(...empty()) }` 모양이었는데, 기록이 빠지면 else 쪽 검사만 남습니다. 그 검사를 잃지 않도록 `DCHECK(load_success || ...empty())`로 줄였습니다.
- 파일에서 더 이상 쓰지 않는 `base/metrics/histogram_macros.h` include를 지웠습니다.
- `tools/metrics/histograms/metadata/others/histograms.xml`에서 네 항목을 지웠습니다.

```diff
-  if (load_success) {
-    RecordNumberOfLoadedNelPolicies(loaded_policies.size());
-  } else {
-    DCHECK(loaded_policies.empty());
-  }
+  DCHECK(load_success || loaded_policies.empty());
```

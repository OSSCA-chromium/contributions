기록 코드가 이미 제거된 만료 히스토그램 3개(`Blink.Overflow.ReplacedElementAreaOutsideContentRect`, `Navigation.HostnameHasDeviationCharacters`, `Media.RTCVideoDecoderMaxInFlightDecodes`)를 각 `histograms.xml` 에서 지웠습니다. 세 디렉터리의 OWNER 가 같은 사람이라 한 CL 로 묶었습니다. 3파일 −34, XML 만 바꾸는 CL 입니다. 그 OWNER toyoshim@ 가 먼저 승인하면서 커밋 메시지의 폐기 태그 형식을 짚어 주어 설명만 고쳤고, `metadata/navigation` OWNER nhiroki@ 를 두 번째 리뷰어로 더해 승인과 CQ 를 받아 2026-10-06(UTC)에 머지됐습니다([c3df4ab3db9f5](https://crrev.com/c3df4ab3db9f5595492f87a5673f751ca9f7f9b3)).

## 문제 설명

- 공식 정리 작업 메타 버그: https://crbug.com/499059525
- 세 히스토그램은 2023-11 ~ 2024-06 에 만료됐고, 기록 코드는 각각 [crrev.com/c/7718450](https://crrev.com/c/7718450)(overflow 카운터 정리), [crrev.com/c/6020762](https://crrev.com/c/6020762)(오래된 IDNA 지표 삭제), [crrev.com/c/5872943](https://crrev.com/c/5872943)(RTCDecoderStreamAdapter 삭제)에서 사라졌습니다.

## 해결 내용

- `metadata/{blink,navigation,media}/histograms.xml` 에서 3항목을 지웠습니다. 전용 enum 은 없었습니다.
- 공식 histogram-cleanup 형식(`[histogram-cleanup]` 제목, 해시태그, `Bug: 499059525`)을 따랐습니다. 폐기 태그는 리뷰에서 `tools/metrics/histograms/README.md` 대로 히스토그램별 단수형 `OBSOLETE_HISTOGRAM[이름]=expired` 로 고쳤습니다.
- 같은 `Media.RTCVideoDecoder*` 중 `FirstFrameLatencyMs` 는 2022년에 만료됐지만 아직 코드가 기록하고 있어, 코드까지 지우는 별도 후보로 남겼습니다.

## 발굴 과정

«기록 코드가 하나도 없는 만료 히스토그램» 스캔의 묶음 중 하나입니다. 이름 전체·접두어·뒷부분 조각 검색이 모두 0건인 것만 고르고, 과거 트리에서 chromium 코드가 기록했던 위치와 그 코드를 지운 CL 을 확인했습니다. 묶음 기준은 공통 OWNER 입니다.

## 테스트 방법

- `validate_format.py` 통과, `pretty_print.py --presubmit` 변경 없음, `git cl format` 변경 없음
- `git cl presubmit --upload` 메시지·경고·오류 0
- XML 만 바뀌어 빌드와 단위 테스트는 해당 없음

## 배운 점

- 같은 접두어의 형제 히스토그램이라도 하나는 기록 코드가 남아 있을 수 있습니다. 항목마다 따로 확인해야 하고, 코드가 남은 것은 다른 종류의 CL 입니다.
- 처음에 쓴 `OBSOLETE_HISTOGRAMS[이름]` 은 두 문법(히스토그램별 단수형 `OBSOLETE_HISTOGRAM[이름]`, CL 전체 복수형 `OBSOLETE_HISTOGRAMS`)을 섞은 형태로, 공식 정리 작업 스킬 문서의 예시를 그대로 따른 것이었습니다. 형식은 스킬 문서보다 `README.md` 원문을 기준으로 삼고, 같은 날 올린 CL 4개도 함께 고쳤습니다.

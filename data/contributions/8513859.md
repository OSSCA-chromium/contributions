`panels/timeline`에 마지막으로 남아 있던 `crbug.com/1172300` 주석을 제거한 컨트리뷰션입니다. 직접 찾은 이슈입니다.

## 문제 설명

- `DropDown.onClick`이 `event.target`에 DevTools가 `Element`에 확장한 메서드를 호출

```ts
private onClick(event: Event): void {
  // TODO(crbug.com/1172300) Ignored during the jsdoc to ts migration
  // @ts-expect-error
  if (!(event.target).enclosingNodeOrSelfWithClass('preview-item')) {
```

- `Event.target`의 타입은 `EventTarget|null`이고 해당 메서드가 없어 그대로는 컴파일되지 않음

## 해결 내용

`(event.target as HTMLElement)`로 캐스팅했습니다.

이슈를 올릴 때는 `instanceof Element` 가드가 필요하고 그러면 동작이 바뀐다고 적었는데, 같은 클래스의 `onMouseMove`를 보고 판단을 바꿨습니다.

```ts
private onMouseMove(event: Event): void {
  const node = (event.target as HTMLElement).enclosingNodeOrSelfWithClass('preview-item');
```

- 9줄 위에서 **같은 가정을 이미 캐스팅으로 처리**하고 있었음
- 두 핸들러 모두 같은 팝오버 내부 요소에 바인딩됨 (`listControl.element`, `contentElement`)
- 가드를 넣으면 지금은 없는 "조용히 return" 분기가 새로 생기므로 오히려 동작 변경

## 테스트 방법

1. `panels/timeline:timeline` 및 `:unittests` 빌드
2. `TimelineHistoryManager.test.ts` → 5/5 통과
3. 동작 변경 없음

## 배운 점

- 같은 파일 안에 이미 선례가 있는지 먼저 확인해야 함
    - 이슈 본문에 "가드가 필요하고 동작 변경에 해당한다"고 단정했는데, 바로 위 함수가 답이었음
    - 억제 주석만 보고 해결 방법을 정하면 파일의 기존 관례와 어긋난 변경을 제안하게 됨
- 가드 추가가 항상 안전한 선택은 아님
    - 지금 코드가 던지는 에러를 조용히 삼키게 되면 문제를 가리는 쪽이 됨

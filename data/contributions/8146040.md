Blink web test 문서의 rebaseline 설명이 현재 코드 구조와 맞지 않는 점이 발견되어, 문서를 수정하였습니다.

## 문제 설명

해결하려는 문제는 Blink web test 문서의 rebaseline 설명이 현재 코드 구조와 맞지 않는 점이었습니다.

- 문서에서 blink_tool.py copy-existing-baselines라는 hidden internal command를 링크하고 있었지만,
    해당 command 파일은 현재 main 브랜치 기준으로 삭제된 상태였습니다.
- 기존 문구는 rebaseline 실행 시 이 command가 내부적으로 항상 실행된다고 설명했지만, 현재 구현에
    서는 별도 command가 아니라 rebaseline.Worker가 BaselineCopier를 직접 호출하는 구조로 바뀌었습니
    다.
- 배경은 Chromium CL 4334979에서 copy-existing-baselines command가 제거되고, 그 역할이
    BaselineCopier 기반의 내부 rebaseline 단계로 흡수된 것입니다.

## 해결 내용

문서가 현재 구현을 설명하도록 보수적으로 수정했습니다.

- 기존 rebaseline fallback 설명의 전체 맥락은 유지했습니다.
- 삭제된 copy-existing-baselines command 링크와 “hidden internal command” 표현을 제거했습니다.
- 현재 동작에 맞게, blink_tool.py rebaseline{,-cl}이 새 baseline 다운로드 전에 내부적으로 필요한
     기존 baseline을 보존한다고 설명했습니다.

변경 전:

This is done in a hidden internal command blink_tool.py copy-existing-baselines,
which is always executed by blink_tool.py rebaseline.

변경 후:

This is handled internally by blink_tool.py rebaseline{,-cl}.

주요 코드 변경은 없고 문서 변경만 수행했습니다.

## 테스트 방법

문서 변경이므로 별도 단위 테스트나 통합 테스트는 수행하지 않았습니다.
로컬호스트를 띄어 실제 문서가 변경된 사항을 확인하였습니다.

## 배운 점

- 처음으로 gerrit 내 PR 생성까지 체험해보았습니다.
- 삭제된 파일의 history 를 검색하는 방식에 대해서 배우게 되었습니다. (log 추적)
- 문서의 최신화는 항상 개발자에게 과제로 남게 된다는 것을 알게 되었습니다.

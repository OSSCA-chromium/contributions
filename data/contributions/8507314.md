DevTools 툴바 필터의 정규식 토글이 코드로 설정한 상태를 반영하지 못하는 버그를 수정한 컨트리뷰션입니다. 직접 찾은 이슈이며, 지금까지의 정리 작업과 달리 실제 동작을 바꾸는 변경입니다.

## 문제 설명

- 정규식 토글을 켠 상태에서 우클릭 `View computed value`를 쓰면 버튼은 켜진 채로 남지만 필터링은 일반 텍스트로 돌아감
- 해당 파일 TODO에 알려진 문제로 기록되어 있었음

```
TODO(b/407751272): ... There is also a bug where the Toolbar Input's regex flag
cannot be controlled, so if you set a regex filter here, the toolbar might not reflect it.
```

`StylePropertyTreeElement.viewComputedValue()`가 정규식 필터를 적용한 뒤 속성명을 문자열로 대입하는데, `filterText` setter는 문자열을 받으면 `#filterIsRegex`를 `false`로 되돌립니다.

```ts
await computedStyleWidget.filterComputedStyles(regex);
computedStyleWidget.filterText = this.property.name;   // string
```

원인 추적 결과 버튼에 상태를 전달할 경로 자체가 없었습니다.

- `#updateView()`가 뷰로 넘기는 입력에 `#filterIsRegex`가 없음
- `ToolbarFilter`가 정규식 버튼을 **생성자 지역 변수**로만 보관
    - `toggled: false`로 고정 생성되고 이후 사용자 클릭으로만 변경
- `ToolbarInputElement.observedAttributes`에도 토글 상태 항목이 없음

## 해결 내용

1. `ToolbarFilter`가 버튼을 필드로 보관하고 `setRegexToggled()` 추가
2. `ToolbarInputElement`에 `regex-toggled` 속성 추가
    - 기존 `value` / `disabled`와 동일하게 `attributeChangedCallback`에서 위임
    - 속성이 `item` 생성보다 먼저 설정된 경우도 반영
3. `ComputedStyleWidget`이 `#filterIsRegex`를 뷰에 전달하고 템플릿에서 바인딩

기존 `regex` 속성은 상태가 아니라 **버튼 표시 여부**라서(생성자 인자명이 `showRegexToggle`) 별도 속성을 추가했습니다.

## 배운 점

- 속성 이름만 보고 의미를 단정하면 안 됨
    - 처음에는 템플릿의 `?regex=${true}` 하드코딩이 버그라고 봤으나, 생성자 인자명이 `showRegexToggle`이라 "버튼 표시 여부"였음
    - 하드코딩은 정상이었고 별도 속성이 필요한 상황이었음
- 테스트 선택자도 구현 세부에 걸림
    - `querySelector('devtools-button')`이 clear 버튼을 먼저 잡았고, `variant`는 getter가 없어 `jslogContext`로 구분해야 했음
- devtools presubmit은 자체 포매터 결과를 커밋하도록 요구
    - `git cl format --dry-run`이 통과해도 별개이며, 포매터 출력이 지저분하면 코드를 고쳐 깔끔한 출력이 나오게 하는 편이 나음

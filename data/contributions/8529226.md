`sql::Statement::ColumnTime()`·`ColumnTimeDelta()` 주석에 남아 있던 손 변환 목록과 TODO 두 개를 지웠습니다. `sql::Statement` 시간 접근자 이행 시리즈(crbug.com/40176243, OSSCA #416)의 일곱 번째이자 마지막 CL입니다. 1파일 −14, 주석만 바뀝니다.

## 문제 설명

- issue url: https://crbug.com/40176243, https://crbug.com/40251269
- `sql/statement.h`의 두 주석은 이 접근자로 바꿔야 할 손 변환(`base::Time::FromInternalValue(ColumnInt64(col))`, `base::Time::FromDeltaSinceWindowsEpoch(base::Microseconds(ColumnInt64(col)))`, `base::TimeDelta::FromInternalValue(ColumnInt64(column_index))`)을 나열하고, 호출하는 곳을 모두 옮긴 뒤 이 목록을 지우라는 TODO를 달고 있었습니다.
- grt@의 [7455767](https://crrev.com/c/7455767)이 한 줄짜리 `BindInt64()` 쓰기를 `BindTime()`·`BindTimeDelta()`로 옮겼고, 이 시리즈의 CL 1~6([8382856](https://crrev.com/c/8382856), [8410045](https://crrev.com/c/8410045), [8474691](https://crrev.com/c/8474691), [8479611](https://crrev.com/c/8479611), [8505857](https://crrev.com/c/8505857), [8521677](https://crrev.com/c/8521677))이 남은 읽기와 쓰기를 옮겼습니다. 여섯 개가 모두 머지되어 TODO가 요구한 일이 끝났습니다.

## 해결 내용

두 주석에서 손 변환 목록과 TODO를 지우고 첫 줄만 남겼습니다.

```diff
   // Conforms with base::Time serialization recommendations.
-  //
-  // This is equivalent to the following snippets, which should be replaced.
-  // * base::Time::FromInternalValue(ColumnInt64(col))
-  // * base::Time::FromDeltaSinceWindowsEpoch(
-  //       base::Microseconds(ColumnInt64(col)))
-  //
-  // TODO(crbug.com/40176243): Migrate all time serialization to this method,
-  // and then remove the migration details above.
   base::Time ColumnTime(int column_index);

   // Conforms with base::TimeDelta deserialization recommendations.
-  //
-  // This is equivalent to the following snippets, which should be replaced.
-  // * base::TimeDelta::FromInternalValue(ColumnInt64(column_index))
-  //
-  // TODO(crbug.com/40251269): Migrate all TimeDelta serialization to this
-  // method and remove the migration details above.
   base::TimeDelta ColumnTimeDelta(int column_index);
```

아직 손으로 변환하는 곳은 CL 설명에 이유와 함께 적었습니다. 모두 이 접근자가 다루지 않는 경우입니다.

- 자동완성 `PaymentsAutofillTable`의 오퍼 만료 시각은 밀리초 단위로 저장합니다.
- `HistoryDatabase`와 IndexedDB SQLite 백엔드는 시각을 `sql::MetaTable`에, `BtmDatabase`는 자체 config 테이블에 둡니다. 둘 다 범용 int64 키-값 저장소입니다.
- record_replay `TaskDatabase`는 시각을 protobuf int64 필드로 다루므로 정리 기준 시각도 int64로 바인딩합니다.
- `VisitDatabase`는 끝이 열린 질의의 종료 시각을 int64 최댓값으로 바인딩합니다. 질의 경계에 쓰는 특수값입니다.

## 발굴 과정

CL 6이 머지된 뒤 최신 main(`148fce6cf91ed`)에서 전수 재검색을 했습니다. 줄바꿈으로 나뉜 문장을 합치고 지역 변수를 거치는 읽기·쓰기까지 따라가는 스캔과, sql을 쓰는 비테스트 파일 113개에서 `FromInternalValue(`·`FromDeltaSinceWindowsEpoch(`·`ToInternalValue()`·`ToDeltaSinceWindowsEpoch()`를 찾는 스캔을 함께 돌렸습니다. 테스트를 빼면 시간 컬럼을 손으로 읽는 곳은 0곳이었습니다. 변환 함수가 남은 9개 파일은 접근자 구현(`sql/statement.cc`) 자신과 위 예외, 그리고 sql 문장 밖의 쓰임(저장 키 문자열, `ColumnTime()`으로 읽은 뒤의 변환)이었습니다. 업로드 직전 main(`8eacc64f42746`, 651커밋 뒤)에서 다시 돌려도 결과가 같았습니다.

리뷰어는 `sql/OWNERS` 중 1부(7455767)를 쓰고 두 버그를 닫은 grt@에게 먼저 받고, 이어서 evanstade@에게 받을 계획입니다.

## 테스트 방법

주석만 지우는 변경이라 빌드와 테스트는 생략했습니다. 대신 위 전수 재검색으로 남은 손 변환이 없다는 것을 확인했습니다.

- `git cl presubmit --upload` 오류 0
- clang-format 결과 변경 없음

## 배운 점

- TODO를 지우는 CL은 «정말 끝났는지»를 보이는 것이 핵심입니다. 단순 grep으로는 여러 줄에 걸친 문장이나 지역 변수를 거치는 변환을 놓칠 수 있어, 문장 단위로 합쳐 보는 스캔을 따로 만들었습니다.
- 남은 예외를 이유와 함께 CL 설명에 적어 두면 리뷰어가 직접 다시 검색하지 않고도 판단할 수 있습니다.
- 빌드가 필요 없는 변경은 필요한 디렉터리만 체크아웃한 sparse worktree(61MB)에서 올릴 수 있어 큰 빌드 트리를 건드리지 않습니다. presubmit이 불러오는 `build/util`·`tools/android/infobar_deprecation` 같은 디렉터리는 함께 체크아웃해야 합니다.

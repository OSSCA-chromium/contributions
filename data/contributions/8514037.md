`panels/timeline`에 남아 있던 `crbug.com/1172300` 억제 4건을 제거한 컨트리뷰션입니다. 직접 찾은 이슈입니다.

## 문제 설명

- jsdoc → ts 마이그레이션 당시 임시로 넣은 억제가 그대로 남아 있었음
- 같은 crbug 번호를 공유하지만 성격이 네 가지로 갈림

```
// TODO(crbug.com/1172300) Ignored during the jsdoc to ts migration
// eslint-disable-next-line @typescript-eslint/no-explicit-any
private currentThreadSetting?: Common.Settings.Setting<any>;
```

## 해결 내용

1. `Setting<any>` 2건에 실제 타입 지정
    - 타입이 설정 생성 지점에 이미 드러나 있었음
    - `'timeline-tree-current-thread'`는 기본값 `0` → `Setting<number>`
    - `'timeline-tree-group-by'`는 기본값 `AggregatedTimelineTreeView.GroupBy.None`이고 해당 enum과만 비교됨 → `Setting<GroupBy>`
2. `TimelineFilmStripOverview.Padding` → `PADDING` 개명
    - naming-convention 억제가 붙어 있던 유일한 건
    - 같은 파일 내 참조 2곳 함께 수정
3. `networkSplitWidget`의 TODO 주석 제거
    - 억제가 붙어 있지 않은 맨 주석이고 타입도 이미 명시되어 있었음

`TimelineHistoryManager.onClick`의 `@ts-expect-error` 1건은 범위에서 제외했습니다. `event.target`을 `enclosingNodeOrSelfWithClass()`에 넘기는 코드로, 타입 지정만으로는 해결되지 않고 런타임 가드가 필요해 동작이 바뀔 수 있습니다. 별도 이슈로 분리했습니다.

## 테스트 방법

1. `panels/timeline:timeline` 및 `:unittests` 빌드
2. `TimelineTreeView.test.ts` + `TimelineFlameChartView.test.ts` + `TimelineEventOverview.test.ts` → 47/47 통과
3. 동작 변경 없음 (타입 선언과 상수명 변경에 한정)

## 배운 점

- 같은 TODO 번호가 붙어 있어도 해결 방법은 제각각
    - 네 건 중 둘은 타입 지정, 하나는 개명, 하나는 단순 삭제였고 나머지 하나는 런타임 가드가 필요해 분리 대상이었음
    - 번호 단위로 묶어 한 번에 처리하려 하면 성격이 다른 변경이 한 CL에 섞임
- `any`의 실제 타입은 대개 선언부가 아니라 **값이 만들어지는 곳**에 있음
    - 두 `Setting` 모두 `createSetting()` 호출의 기본값이 타입을 알려주고 있었음

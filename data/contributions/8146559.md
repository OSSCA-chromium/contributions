docs/speed/perf_waterfall.md에 남아 있던 perf_regression_sheriffing.md 참조 두 건을 최신 링크로 수정하고, 첫 컨트리뷰션을 위해 AUTHORS에 이름을 추가한 컨트리뷰션입니다.

## 문제 설명
- `perf_regression_sheriffing.md` 문서가 삭제 커밋 70d0e9914790a("Remove outdated perf regression gardening docs")에서 제거되면서, docs/speed/README.md의 링크는 함께 정리됐지만 `docs/speed/perf_waterfall.md` 안의 참조 두 곳은 정리되지 않고 그대로 남음
    - Overview 문단의 "[Perf Sheriff Rotation](perf_regression_sheriffing.md)"
    - Links 목록의 "* [Perf Sheriff Rotation](perf_regression_sheriffing.md)"
- 두 링크 모두 더 이상 존재하지 않는 로컬 파일을 가리켜 클릭 시 깨지는 상태

## 해결 내용
1. 두 참조 모두 삭제된 문서가 원래 안내하던 목적지와 동일한 http://goto.google.com/chrome-perf-regression-sheriffing 링크로 교체
2. 바로 이웃한 "[Perfbot Health Sheriffing Rotation](http://goto.google.com/perf-bot-health-sheriffs)" 링크와 동일한 goto 단축링크 형식으로 통일
3. 첫 컨트리뷰션이라 AUTHORS 파일에 본인 이름을 한 줄 추가 (같은 커밋에 포함)

## 테스트 방법
- Gitiles에서 삭제 커밋 70d0e9914790a의 diff를 확인, README.md에서는 이미 제거됐지만 `perf_waterfall.md`에는 반영되지 않았음을 교차 확인
- Code Search로 저장소 전체에서 `perf_regression_sheriffing.md` 참조를 재검색해, 이번 CL의 스코프인 perf_waterfall.md 두 곳이 모두 정리됐는지 확인
- Code-Owners 승인 확보 및 CQ 체크 6개 통과, Tree 상태 정상 확인

## 배운 점
- 문서를 변경하는 커밋을 진행할 때, 작업 전 history 탐색과 맥락 파악이 매우 중요함.
- 첫 CL에는 AUTHORS 등록이 필요하며, Code-Owners 승인 여부가 Submit Requirements에 별도로 표시됨

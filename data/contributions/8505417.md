QuotaManagerImpl 인스턴스 메서드의 시퀀스 검사를 일관되게 추가하고, 저장 공간 압박 콜백 등록을 IO 스레드로 옮겼습니다. 테스트용 manager 생성 과정이 잘못된 시퀀스에 고정되지 않도록 수정했습니다.

## 문제 설명

일부 콜백·인라인 접근자·테스트 헬퍼에는 `DCHECK_CALLED_ON_VALID_SEQUENCE`가 빠져 있었습니다. 검사를 추가하면서 `StoragePartitionImpl`의 콜백 등록도 manager의 시퀀스 규칙에 맞춰야 했고, MockQuotaManager 생성자의 불필요한 setter 호출도 정리할 필요가 있었습니다.

## 해결 내용

1. 삭제 콜백, 할당량·사용량 조회, storage pressure 처리, 소멸자, 인라인 접근자와 테스트 헬퍼 등에 시퀀스 DCHECK을 추가합니다.
2. `StoragePartitionImpl`에서 `SetStoragePressureCallback()` 등록 작업을 IO 스레드로 게시합니다.
3. `MockQuotaManager` 생성자의 중복 `SetEvictionDisabledForTesting(false)` 호출을 제거해 생성 시점에는 시퀀스 검사가 분리된 상태를 유지합니다.

## 테스트 방법

- `SettingsOnWrongSequence`와 `StoragePressureCallbackOnWrongSequence`는 다른 스레드에서 호출하면 DCHECK에 걸리는지 검사합니다.
- `ConstructOnDifferentSequence`는 worker에서 mock을 만든 뒤 지정된 시퀀스에서 설정을 읽고 쓰는 동작이 가능함을 확인합니다.

Gerrit 기록상 Patch Set 2는 2026-10-02 UTC에 CQ 실행을 통과했습니다. 보고서 작성 과정에서 Chromium 테스트를 별도로 실행하지는 않았습니다.

## 배운 점

- 시퀀스 검사 추가는 메서드 입구의 매크로 삽입뿐 아니라 실제 호출자가 어느 시퀀스에서 동작하는지 확인하는 작업입니다.
- 생성 시퀀스와 사용 시퀀스가 다른 객체는 생성자에서 호출하는 작은 헬퍼도 시퀀스 바인딩에 영향을 줄 수 있습니다.

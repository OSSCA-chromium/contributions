SecurityOriginView의 `Certificate Transparency section`을 Lit으로 전환했습니다. CT compliance 안내
문구, Signed Certificate Timestamp(SCT) 표시, 상세 보기 전환 테스트를 추가했습니다.

## 문제 설명

`Certificate Transparency section`은 SCT 요약·상세 정보와 CT compliance 안내 문구를 DOM 생성 코드로
구성하고, 버튼 클릭 시 클래스와 접근성 속성을 직접 변경하고 있었습니다.
이 영역을 Lit 템플릿과 표시 상태에 따라 렌더링하도록 전환하는 작업입니다.

## 해결 내용

- SCT 요약, 상세 정보, CT compliance 안내 문구를 각각 Lit 템플릿으로 만들고,
  `renderCertificateTransparencySection()`에서 함께 렌더링하도록 했습니다.
- `#createCertificateTransparencySection()`에서 상세 표시 상태를 관리하고,
  클릭 시 요약·상세 정보의 표시와 버튼 문구·접근성 속성을 함께 갱신합니다.
- SCT가 없고 CT compliance가 `Unknown`이면 영역을 생략하는 기존 조건을 유지했습니다.
  CT compliance가 `Unknown`인 경우 안내 문구도 표시하지 않습니다.
- `renderDetailsTable()`에 추가 클래스를 전달할 수 있도록 확장하고,
  더 이상 사용하지 않는 `SecurityDetailsTable` 클래스를 제거했습니다.
- `Compliant`·`NotCompliant` 두 경우를 포함해 단위 테스트 6개를 추가했습니다.

## 테스트 방법

`SecurityPanel.test.ts`에 다음 내용을 검증하는 단위 테스트 6개를 추가했습니다.

- 제목과 접근성 속성, SCT 요약·상세 정보 및 표시 형식 확인
- SCT가 없고 CT compliance가 `Unknown`이면 `CT section`과 `note section`이 생략되는지 확인
- SCT가 있고 CT compliance가 `Unknown`이면 `CT section`은 표시하고 CT compliance 안내 문구는 생략하는지 확인
- `Compliant`와 `NotCompliant` 각각에 맞는 안내 문구 확인
- 상세 보기 버튼 클릭 시 요약은 숨기고 상세 정보는 표시하며, 버튼 문구와
  `accessibleLabel`·`accessibleExpanded`가 갱신되는지 확인

Chromium 보안 웹 테스트 2개의 기대값은 CL 8425664에서 임시 조정했습니다.
최종 patchset의 CQ 실행이 통과했으며, 2026년 9월 23일(한국 시간)
DevTools main에 병합되었습니다.

## 배운 점

- 표시 전환을 검증할 때는 텍스트뿐 아니라 실제 표시 여부와 접근성 상태도
  함께 확인해야 합니다.
- 리뷰에서 `CT section`을 생략하면 `note section`도 생략되는 기존 동작을 확인했습니다.
  이 CL은 Lit 전환에 집중하고, 해당 동작 수정은 후속 CL로 진행하기로 했습니다.

QuotaManager 내부와 사용량 추적기가 항상 유효한 SpecialStoragePolicy를 갖도록 정리했습니다. 정책을 생략하는 embedder에는 특별 권한을 부여하지 않는 기본 정책을 제공해 기존 호출 계약을 유지합니다.

## 문제 설명

quota 내부에서는 정책 포인터가 있는지에 따라 권한 조회와 observer 등록·해제 경로를 나눴습니다. 내부에서 null을 금지하는 것만으로 정리하면 정책을 생략하는 WebView·Headless·Cast·content shell의 사용 방식과 충돌할 수 있습니다.

## 해결 내용

1. 공개 `QuotaManager` 경계에서 정책이 생략되면 `DefaultSpecialStoragePolicy`를 생성합니다. 보호·무제한·영구 저장 등 특별 권한 조회에 모두 false를 반환합니다.
2. `QuotaManagerImpl`, `UsageTracker`, `ClientUsageTracker` 생성 시 정책이 null이 아닌지 CHECK하고 내부의 반복적인 null 분기를 제거합니다.
3. 정책 참조를 유지하며 observer를 일관되게 등록·해제하도록 합니다. proxy 테스트에도 `MockSpecialStoragePolicy`를 명시적으로 제공합니다.

## 테스트 방법

- `RejectsNullSpecialStoragePolicy`는 내부 `QuotaManagerImpl`을 null 정책으로 만들면 CHECK에 걸리는지 확인합니다.
- `QuotaManagerWithoutSpecialStoragePolicy`는 공개 경계에서 정책을 생략해도 일반 quota가 적용되고 무제한 사용량은 0인지 검증합니다. 사용량 추적기를 재생성한 뒤에도 같은 사용량이 유지되는지 확인합니다.

Gerrit 기록상 Patch Set 1는 2026-10-01 UTC에 CQ 실행을 통과했습니다. 보고서 작성 과정에서 Chromium 테스트를 별도로 실행하지는 않았습니다.

## 관련 이슈와 외부 PR

- [관련 Chromium 이슈 40825886](https://crbug.com/40825886)

패치 설명은 [기존 CL 3505537](https://crrev.com/c/3505537)의 invariant 제안을 embedder의 정책 생략 계약을 보존하는 방식으로 다시 다룬다고 설명합니다.

## 배운 점

- 내부의 non-null 규칙을 강화할 때는 공개 API가 허용하던 생략 의미를 경계에서 보존해야 합니다.
- 아무 특별 권한도 주지 않는 기본 객체를 사용하면 조회와 observer 수명 관리를 한 경로로 정리할 수 있습니다.

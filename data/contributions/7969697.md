SecurityOriginView의 보안 상태 아이콘과 Origin URL 표시를 Lit 템플릿으로 전환했습니다.

## 문제 설명

`SecurityOriginView`는 보안 상태 아이콘과 URL 표시를 DOM 생성·수정 코드로
구성하고 있었습니다. 이 부분을 Lit 템플릿으로 옮겨 생성 시점과 보안 상태
변경 시점에 같은 렌더링 함수를 사용하도록 했습니다.

## 해결 내용

- URL을 Lit 템플릿으로 만드는 `renderHighlightedUrl()`을 추가했습니다.
  `://`가 없는 URL은 일반 텍스트로, 있는 URL은 보안 상태에 따라 scheme을
  강조하도록 했습니다.
- `#renderOriginDisplay()`에서 아이콘과 URL을 함께 렌더링하고, 생성자와
  `setSecurityState()`에서 호출하도록 했습니다.
- `SecurityPanelSidebar`는 `Element`를 필요로 하므로, 기존
  `createHighlightedUrl()`은 Lit 결과를 렌더링한 요소를 반환하는 함수로 유지했습니다.
- URL 표시를 확인하는 단위 테스트 2개와 `AUTHORS` 항목을 추가했습니다.

## 테스트 방법

`SecurityPanel.test.ts`에 다음 두 단위 테스트를 추가했습니다.

- `foo.bar`처럼 `://`가 없는 URL은 강조 없이 표시되는지 확인
- `https://foo.bar`는 URL 텍스트와 scheme의 강조 클래스, `://` 표시가 올바른지 확인

리뷰 과정에서 DOM 구조를 출력하는 Chromium 웹 테스트의 실패를 확인했습니다.
리뷰어 안내에 따라 CL 8038580에서 기대값을 임시 완화하고, 변경이 Chromium에
반영된 뒤 CL 8042189에서 기대 결과를 갱신했습니다.
이 CL은 CQ를 거쳐 2026년 7월 4일(한국 시간) DevTools main에 병합되었습니다.

## 배운 점

- Lit 전환 시 호출부가 템플릿과 DOM 요소 중 무엇을 필요로 하는지 확인해야 합니다.
  Origin 표시에는 템플릿을 직접 사용하고, Sidebar에는 요소를 반환하는 함수를
  유지했습니다.
- DOM을 출력하는 테스트는 Lit이 추가하는 주석 노드나 요소 구조 변경에도
  영향을 받으므로, Chromium 쪽 기대 결과도 함께 확인해야 합니다.

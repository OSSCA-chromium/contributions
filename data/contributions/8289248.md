SecurityOriginView의 `title section`을 Lit으로 전환했습니다. 렌더링, `security state` 갱신,
Network panel에서 해당 Origin의 요청을 표시하는 동작의 테스트를 추가했습니다.

## 문제 설명

`SecurityOriginView`의 `title section`에서는 Origin 아이콘과 URL만 Lit으로
렌더링하고, 제목과 Network panel 버튼은 DOM 생성·수정 코드로 구성하고
있었습니다. 이 영역 전체를 Lit 템플릿으로 전환하는 작업입니다.

## 해결 내용

- `renderTitleSection()`에서 제목, `security state` 아이콘, URL, Network panel 버튼을
  함께 렌더링하도록 했습니다. 생성자와 `setSecurityState()`에서
  `#renderTitleSection()`을 호출합니다.
- 아이콘 이름을 반환하는 함수를 분리해 Lit 템플릿에서 사용하고, 기존 아이콘
  요소 생성 함수도 이 함수를 사용하도록 했습니다.
- Network panel 버튼을 Lit 템플릿에 선언하고, 클릭 처리를 `#revealInNetwork`로
  옮겼습니다. Origin의 host와 scheme을 요청 필터로 전달하는 동작은 유지했습니다.
- 제목의 `role="heading"`과 `aria-level="1"`을 유지했습니다. 리뷰 의견에 따라
  버튼의 `role="link"` 지정과 이를 확인하던 테스트 assertion은 제거했습니다.
- `title section`의 단위 테스트 3개와 테스트에 필요한 빌드 의존성을 추가했습니다.

## 테스트 방법

`SecurityPanel.test.ts`에 다음 세 단위 테스트를 추가했습니다.

- 제목과 제목의 접근성 속성, Origin URL, Network panel 버튼 문구 확인
- `security state`를 `Secure`에서 `Insecure`로 바꾸면 아이콘과 URL scheme의 클래스가
  갱신되는지 확인
- 버튼 클릭 시 Revealer가 한 번 호출되고, `foo.bar`와 `https`가 각각
  Domain과 Scheme 필터로 전달되는지 확인

리뷰 중 Chromium 보안 웹 테스트 4개의 실패가 보고되어, CL 8297118에서
기대값을 임시 조정했습니다. 최종 patchset의 CQ 실행은 통과했으며,
2026년 9월 10일(한국 시간) DevTools main에 병합되었습니다.

## 배운 점

- 일부만 Lit으로 전환된 영역을 확장할 때는 초기 렌더링뿐 아니라 상태 변경과
  버튼 클릭 동작도 함께 검증해야 합니다.
- 커스텀 버튼의 접근성 처리는 바깥 요소와 내부의 실제 버튼을 구분해서
  확인해야 합니다. 이 CL에서는 리뷰를 통해 `role="link"` 지정을 제거했습니다.

SecurityOriginView의 `connection section`을 Lit으로 전환했습니다. `protocol`, `key exchange`,
`server signature`, `cipher`, Encrypted ClientHello 표시 테스트를 추가하고,
`security details`가 없으면 이 영역을 표시하지 않는지 검증했습니다.

## 문제 설명

`SecurityOriginView`는 연결 정보의 제목과 표를 DOM 생성·수정 코드로 구성하고
있었습니다. 표시할 값을 만드는 로직을 분리하고, 이 영역을 Lit 템플릿으로
전환하는 작업입니다.

## 해결 내용

- `buildConnectionDetailsRows()`에서 표시할 행 데이터를 만들고,
  `renderDetailsTable()`과 `renderConnectionSection()`에서 표와 제목을
  Lit으로 렌더링하도록 했습니다.
- `key exchange` 알고리즘과 그룹의 표시를 `formatKeyExchange()`로 분리했습니다.
  `server signature`, MAC, Encrypted ClientHello의 기존 표시 조건도 유지했습니다.
- 영역에 `connection-section` 클래스를 추가하고, `security details`가 있을 때만
  생성하도록 했습니다. 제목의 `role="heading"`과 `aria-level="2"`도 유지했습니다.
- 테스트 데이터에서 개별 보안 정보를 지정할 수 있도록 헬퍼를 수정하고,
  `connection section`의 단위 테스트 15개를 추가했습니다.

+function formatKeyExchange(securityDetails: Protocol.Network.SecurityDetails): string|null {
+  // A TLS connection negotiates a cipher suite and, when doing an ephemeral
+  // ECDH key exchange, a "named group". In TLS 1.2, the cipher suite is
+  // named like TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256. The DevTools protocol
+  // tried to decompose this name and calls the "ECDHE_RSA" portion the
+  // "keyExchange", because it determined the rough shape of the key
+  // exchange portion of the handshake. (A keyExchange of "RSA" meant a very
+  // different handshake set.) But ECDHE_RSA was still parameterized by a
+  // named group (e.g. X25519), which the DevTools protocol exposes as
+  // "keyExchangeGroup".
+  //
+  // Then, starting TLS 1.3, the cipher suites are named like
+  // TLS_AES_128_GCM_SHA256. The handshake shape is implicit in the
+  // protocol. keyExchange is empty and we only have keyExchangeGroup.
+  //
+  // "Key exchange group" isn't common terminology and, in TLS 1.3,
+  // something like "X25519" is better labelled as "key exchange" than "key
+  // exchange group" anyway. So combine the two fields when displaying in
+  // the UI.
+  if (securityDetails.keyExchange && securityDetails.keyExchangeGroup) {
+    return securityDetails.keyExchange + ' with ' + securityDetails.keyExchangeGroup;
+  }
+  return securityDetails.keyExchange || securityDetails.keyExchangeGroup || null;
+}

## 테스트 방법

`SecurityPanel.test.ts`에 다음 내용을 검증하는 단위 테스트 15개를 추가했습니다.

- 제목과 접근성 속성, 행의 표시 순서, `protocol` 표시
- `security details`가 없을 때 `connection section` 생략
- `key exchange` 알고리즘과 그룹이 모두 있거나, 하나만 있거나, 모두 없는 경우
- `server signature` 알고리즘이 알려진 값이거나, 알 수 없는 값이거나, 없는 경우
- MAC 유무에 따른 `cipher` 표시와 Encrypted ClientHello 활성화 여부

리뷰 중 Chromium 보안 웹 테스트 2개의 실패가 보고되어, CL 8302454에서
기대값을 임시 조정했습니다. 이후 CQ 실행이 통과했으며,
2026년 8월 28일(한국 시간) DevTools main에 병합되었습니다.

## 배운 점

- UI를 Lit으로 전환할 때는 값의 표시 형식과 조건부 행의 생략 동작을 함께
  검증해야 합니다.
- 테스트 데이터를 필요한 필드만 바꿀 수 있게 구성하면 여러 입력 조합을
  간결하게 검증할 수 있습니다.

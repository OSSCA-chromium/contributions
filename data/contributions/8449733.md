Chromium의 `failed-request.js`를 DevTools unit test로 옮겼습니다.
실패한 request의 origin이 Security sidebar에 올바르게 표시되는지 검증합니다.

## 문제 설명

기존 테스트는 Security sidebar의 DOM 출력을 기대 결과와 비교해, DOM 구조 변경에도
기대 결과 갱신이 필요했습니다. 이를 unit test로 옮겨 group과 origin을 직접 검증하도록 했습니다.

## 해결 내용

- `SecurityPanel.test.ts`에 unit test 1개를 추가했습니다.
- 기존 테스트와 같은 URL과 `documentURL`로 request 2개를 만들고,
  하나는 `Secure`, 다른 하나는 security state를 unknown으로 유지했습니다.
- `RequestFinished` 이벤트를 전달하고 `doubleRaf()`로 렌더링을 기다렸습니다.
- 보이는 group이 `Main origin`, `Secure origins`, `Unknown / canceled`이며,
  전체 origin 항목이 2개인지 확인했습니다.
- `Secure origins`에는 `https://foo.test`, `Unknown / canceled`에는
  `https://does-not-resolve.test`가 각각 하나씩 표시되는지 검증했습니다.

기존 Chromium 테스트와 기대 결과 파일의 제거는 후속 CL 8460722에서 진행했습니다.

## 테스트 방법

CQ를 통해 2026년 9월 24일(한국 시간) DevTools main에 병합되었습니다.

## 배운 점

origin의 표시 여부뿐 아니라 group 분류와 전체 항목 수를 함께 검증해야
누락되거나 잘못 분류된 origin도 확인할 수 있습니다.

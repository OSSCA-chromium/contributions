기록 코드가 이미 제거된 만료 히스토그램 10개를 `metadata/{download,password,safe_browsing}` 의 `histograms.xml` 에서 지우고, 이것만 쓰던 enum 4개를 함께 정리했습니다. 세 디렉터리의 OWNER 가 같은 사람이라 한 CL 로 묶었습니다. 6파일 −131, XML 만 바꾸는 CL 입니다.

## 문제 설명

- 공식 정리 작업 메타 버그: https://crbug.com/499059525
- `Download.Later.*` 3개는 2022년에 만료됐고 `DownloadLaterMetrics.java` 가 [crrev.com/c/3765300](https://crrev.com/c/3765300)에서 사라졌습니다.
- `PasswordManager.ExportAndroid.*` 3개는 2025-03 만료, [crrev.com/c/6787824](https://crrev.com/c/6787824)에서 기록 코드가 삭제됐습니다. `PasswordManager.AutomaticChange.AcceptanceWithoutAutoButton` 은 [crrev.com/c/6793022](https://crrev.com/c/6793022), `SafeBrowsing.AdvancedProtection.Enabled` 는 [crrev.com/c/6549936](https://crrev.com/c/6549936)에서 사라졌습니다.

## 해결 내용

- 10항목을 지우고, 이것만 쓰던 enum `DownloadLaterDialogChoice`·`DownloadLaterUiEvent`·`PasswordCheckResolutionAction`·`AdvancedProtectionEnabledStatus` 를 지웠습니다. `PlatformFileError` 는 다른 히스토그램 30여 개가 써서 남겼습니다.
- 패턴 이름(`Download.Later.UI.DialogChoice{DownloadDialogSource}`)도 변형 전부가 기록되지 않는 것을 확인하고 지웠습니다.
- 공식 histogram-cleanup 형식(`[histogram-cleanup]`, `OBSOLETE_HISTOGRAMS[…]=expired`, 해시태그, `Bug: 499059525`).

## 발굴 과정

«기록 코드가 하나도 없는 만료 히스토그램» 스캔에서 나온 묶음입니다. 묶음 기준을 디렉터리가 아니라 **공통 OWNER** 로 잡았습니다. 한 사람이 여러 `metadata/` 디렉터리의 OWNER 면 한 CL 로 묶어야 리뷰어 한 명의 승인으로 끝나고, 리뷰어 수도 늘지 않기 때문입니다. 각 이름은 접두어·뒷부분 조각 검색으로 조합 기록이 없는지 확인하고, 과거 트리에서 실제 기록 위치와 그 코드를 지운 CL 을 찾아 적었습니다.

## 테스트 방법

- `validate_format.py` 통과, `pretty_print.py --presubmit` 변경 없음, `git cl format` 변경 없음
- `git cl presubmit --upload` 통과
- XML 만 바뀌어 빌드와 단위 테스트는 해당 없음

## 배운 점

- 정리 CL 의 묶음 단위는 «같은 OWNER» 가 가장 좋습니다. 디렉터리별로 쪼개면 CL 수만 늘고 리뷰어도 늘어납니다.
- enum 을 지울 때는 그 enum 을 쓰는 다른 히스토그램이 남아 있는지 반드시 세어야 합니다. 이름이 비슷한 공용 enum 이 많습니다.

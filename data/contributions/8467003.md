Chromium의 `mixed-content-active-and-passive-reload.js`를 DevTools unit test로 옮겼습니다.
request가 기록되면 active·passive mixed content의 reload 안내가 Network panel 링크로
바뀌는지 검증합니다.

## 문제 설명

기존 테스트는 request 기록 전후의 DOM 출력을 기대 결과와 비교해, DOM 구조 변경에도
기대 결과 갱신이 필요했습니다. 이를 unit test로 옮겨 안내 문구의 전환을 직접 검증하도록 했습니다.

## 해결 내용

- `SecurityPanel.test.ts`에 unit test 1개를 추가했습니다.
- active·passive mixed content가 있는 security state를 전달한 뒤,
  두 설명에 reload 안내가 표시되는지 확인했습니다.
- 같은 security state 이벤트를 다시 전달하고, `OptionallyBlockable`과 `Blockable`
  request의 `RequestFinished` 이벤트를 순서대로 전달했습니다.
- 두 안내가 각각 `View 1 request in Network panel` 문구와 `role="link"`를 갖는
  링크로 바뀌는지 검증했습니다.
- request 기록 전후에 설명이 2개이며, 각 설명의 상태 class·제목·본문이 유지되는지도
  확인했습니다.

기존 Chromium 테스트와 기대 결과 파일의 제거는 후속 CL 8483194에서 진행했습니다.

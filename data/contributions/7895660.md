Apple에서 디렉터리를 비재귀적으로 감시할 때, 내부 파일의 내용을 수정해도
`FilePathWatcher` 이벤트가 추가로 발생하지 않는 동작을 테스트로 검증했습니다.

## 문제 설명

`base/files/file_path_watcher_unittest.cc`의
`FilePathWatcherTest.WatchDirectory`는 디렉터리를 감시하면서 내부 파일의
생성, 수정, 삭제에 따른 이벤트를 확인하는 테스트입니다.

당시 Apple 구현은 비재귀 디렉터리 감시에서 내부 파일의 내용 변경을 감지하지
않았습니다. 기존 테스트는 `#if !BUILDFLAG(IS_APPLE)` 조건으로 파일 수정 단계
자체를 제외하고, Apple에서 이벤트가 발생하지 않는지 확인하라는 TODO만
남겨 두었습니다.

## 해결 내용

`WriteFile(file1, "content v2")`를 플랫폼 조건문 밖으로 옮겨 Apple에서도
기존 파일의 내용을 수정하도록 했습니다. 이후 Apple에서는 새 기대 이벤트를
추가하지 않고, 기존 기대 목록과 실제 수신 목록이 일치하는지 확인했습니다.

Apple 분기에서 추가한 검증은 다음과 같습니다.

```cpp
delegate.RunUntilEventsMatch(event_expecter.GetMatcher(),
                             ExpectedEventsSinceLastWait::kNone);
```

`ExpectedEventsSinceLastWait::kNone`을 전달하면 이벤트 루프를 잠시 실행한 뒤
목록을 비교합니다. 파일 감시 알림은 나중에 전달될 수 있으므로, 이렇게 해야
검사 시점에 아직 도착하지 않은 예상 밖의 이벤트를 놓치지 않을 수 있습니다.

이 테스트는 앞선 디렉터리와 파일 생성 이벤트를 목록에 누적합니다. 따라서 파일
수정 뒤에는 목록이 비어 있는지가 아니라, 기존 기대 목록에서 이벤트가 더
늘어나지 않았는지를 검증합니다. 다른 플랫폼의 파일 수정 이벤트 기대값과
이후 파일 삭제 및 새 파일 생성 검증은 유지했습니다.

리뷰에서는 Chromium 이슈 `40263777`이 `321980307`의 중복 이슈로 처리되어
있다는 의견을 받아, 커밋 메시지의 `Bug:`에 두 번호를 모두 기록했습니다.

## 테스트 방법

CL의 커밋 메시지에 기록된 검증 대상은 다음과 같습니다.

```bash
base_unittests --gtest_filter=FilePathWatcherTest.WatchDirectory
```

Gerrit에서 CQ 실행과 최종 제출을 확인했으며,
2026년 6월 9일 Chromium main에 병합되었습니다.

## 배운 점

- 플랫폼마다 기대 동작이 다를 때도 해당 동작을 실행하고 결과를 확인하면
  테스트 범위를 넓힐 수 있습니다. Apple에서도 파일을 수정한 뒤 알림이
  추가되지 않는지 검증하도록 보완했습니다.
- 이벤트를 누적하는 테스트에서는 이전 단계의 기록을 고려해야 합니다.
  이번 검증은 기존 이벤트를 포함한 목록을 비교하여 새 이벤트가 없음을 확인합니다.
- 리뷰에서 중복 처리된 이슈의 연결 관계를 확인하고 커밋 메시지에 반영하면,
  변경 내용과 관련 논의를 함께 추적하는 데 도움이 됩니다.

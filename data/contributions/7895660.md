Apple에서 디렉터리를 비재귀적으로 감시할 때 내부 파일의 내용을 수정해도 이벤트가 발생하지 않는 동작을 검증하도록 테스트를 보완했습니다.

## 문제 설명

`FilePathWatcherTest.WatchDirectory`는 Apple에서 파일 수정 단계를 건너뛰고,
이벤트가 발생하지 않는지 확인하라는 TODO만 남겨 두었습니다.

이 테스트에서 사용하는 Apple의 비재귀 감시(`kNonRecursive`)는
`kqueue`로 디렉터리 경로를 감시하며, 내부 파일은 개별 감시하지 않습니다.
파일 생성·삭제는 디렉터리의 항목 목록을 바꾸므로 감지됩니다.
반면 기존 파일의 내용만 수정하면 항목 목록은 그대로이므로,
이 감시 방식에서는 이벤트가 보고되지 않습니다.

## 해결 내용

Apple에서도 `WriteFile()`로 파일을 수정하고, 이벤트가 추가되지 않았는지
확인하도록 변경했습니다. 전체 코드 diff는 다음과 같습니다.

```diff

   }
```

이벤트 루프를 잠시 실행한 뒤, 실제 수신 목록이 이전 단계까지의 기대 목록과
일치하는지 비교합니다. 비동기 알림이 늦게 도착하는 경우도 확인하기 위해서입니다.

## 테스트 방법

CL에 기록한 테스트는 다음과 같습니다.

```bash
base_unittests --gtest_filter=FilePathWatcherTest.WatchDirectory
```

CQ를 거쳐 2026년 6월 9일 Chromium main에 병합되었습니다.

## 배운 점

- 플랫폼별로 이벤트가 발생하지 않는 동작도 테스트로 명시할 수 있습니다.
- 이벤트를 누적하는 테스트에서는 기존 목록을 비교해 새 이벤트가 없음을 확인합니다.

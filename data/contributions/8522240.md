MSE의 MP3·ADTS 파서를 Rust 구현으로 바꾸면서 남겨 둔 플래그 `kRustMpegAudioDataParser`와, 그 플래그가 꺼졌을 때만 쓰이던 C++ 파싱 경로를 지웠습니다. 플래그 작성자가 «M152 stable 뒤에 제거»라고 적어 둔 것을 M155가 stable인 시점에 정리한 것으로, 8파일 +114/−514, 동작은 바뀌지 않습니다.

## 문제 설명

- [crrev.com/c8cf5c6948fe2](https://crrev.com/c8cf5c6948fe2)(2026-07, dalecurtis@)가 MSE용 MPEG-1 오디오(MP3)·ADTS 파서를 Rust로 다시 쓰면서, 되돌릴 수 있도록 플래그 `kRustMpegAudioDataParser`(기본 켜짐)를 두고 «Remove after M152 stable»이라는 주석을 달았습니다.
- M152는 2026-08-25에 stable이 됐고 트리는 M157입니다. 플래그는 한 번도 꺼진 적이 없어, `MPEGAudioStreamParserBase::Parse()`의 C++ 경로(`ParseLegacy()`)와 그 경로만 쓰는 헬퍼가 죽은 코드로 남아 있었습니다.
- 지운 C++ 경로에는 `UNSAFE_TODO`로 표시된 포인터 연산이 15곳 있었습니다.

## 해결 내용

- `media/base/media_switches.{cc,h}`에서 플래그 정의·선언을 지웠습니다.
- `MPEGAudioStreamParserBase`에서 Rust 경로(`ParseRust()`)의 본문을 `Parse()`로 합치고, C++ 경로만 쓰던 `ParseLegacy()`·`ParseFrame()`·Icecast/ID3v1/ID3v2 처리·`ParseSyncSafeInt()`·`FindNextValidStartCode()`·`LocateEndOfHeaders()`와 상수 7개, start code mask 멤버를 지웠습니다.
- ADTS·MPEG-1 서브클래스에서 C++ 경로용 오버라이드(`GetMinHeaderSize()`·`ParseFrameHeader()`)와 로그 제한 카운터를 지우고, 생성자에서 start code mask 인자를 뺐습니다. 그 오버라이드만 쓰던 `media_log()` 접근자와 쓰지 않게 된 include도 정리했습니다.
- 다른 코드가 쓰는 헤더 헬퍼(`ParseHeader()`, `kHeaderSize`)는 남겼습니다.

```diff
 StreamParser::ParseStatus MPEGAudioStreamParserBase::Parse(
     int max_pending_bytes_to_inspect) {
   ...
-  if (base::FeatureList::IsEnabled(kRustMpegAudioDataParser)) {
-    return ParseRust(max_pending_bytes_to_inspect);
-  }
-  return ParseLegacy(max_pending_bytes_to_inspect);
-}
+  base::span<const uint8_t> queue_span = queue_.Data();
+  ...  // 이전 ParseRust() 본문
```

## 발굴 과정

리뷰어 신뢰를 쌓기 위해 지금까지 승인을 많이 받은 영역(media·net·storage)으로 범위를 좁힌 스캔에서, «Remove after M<n>» 형태의 제거 예정 주석을 훑다가 찾았습니다. 주석의 마일스톤이 지났는지는 chromiumdash의 stable 날짜로 확인했습니다. 같은 스캔에서 나온 `kPauseBackgroundTimer` 정리(8522238)를 플래그 작성자인 dalecurtis@가 승인한 뒤, 같은 리뷰어에게 이어서 보냈습니다.

## 테스트 방법

동작 불변 정리라 새 테스트는 없고 기존 테스트 통과가 검증입니다.

- `media_unittests` 증분 빌드 후 `--gtest_filter='*MPEG1AudioStreamParser*:*ADTS*:*Mp3*:*MP3*:*StreamParserTest*'` **60/60** — MPEG-1 파서, MP3 seek, `AudioFileReader`, 파이프라인 통합, `StreamParser` 테스트
- 기존 단위 테스트는 플래그를 건드리지 않아 원래부터 Rust 경로만 검증하고 있었습니다(테스트 변경 0).
- ADTS 파서와 그 테스트는 `proprietary_codecs` 빌드에서만 컴파일되어 로컬 빌드에 없습니다. 지운 심볼을 참조하는 곳과 지운 include에 기대던 파일이 없는지 직접 확인하고, 컴파일은 CQ에 맡겼습니다.
- `git cl presubmit --upload` 경고 0

## 배운 점

- «Remove after M<n> stable» 주석은 트렁크 번호가 아니라 **stable 출시 날짜**로 판단합니다. chromiumdash 마일스톤 일정에서 M152 stable(2026-08-25)을 확인한 뒤 착수했습니다.
- 조건부로 빌드되는 파일(`proprietary_codecs`)은 로컬 테스트 필터에 0건으로 잡힙니다. 0건은 «통과»가 아니라 «안 돌았음»이므로, 그 파일은 따로 검토해야 합니다.

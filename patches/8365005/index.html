chrome/browser/webauthn 디렉토리 내 crypto/sha2.h를 crypto/hash.h로 마이그레이션

문제 설명

기존 crypto/sha2.h와 crypto/secure_hash.h를 제거하기 위해, 이를 사용하는 코드를 crypto/hash.h의 API로 전환하는 작업입니다.

해결 내용

  • 기존 SHA-256 API를 새 API로 변경했습니다.
    enclave_manager.cc의 crypto::SHA256Hash()를 crypto::hash::Sha256()으로, crypto::kSHA256Length를 crypto::hash::kSha256Size로 변경했습니다.

  • 불필요한 헤더를 제거했습니다.
    enclave_manager.cc와 fake_recovery_key_store.cc에서 crypto/sha2.h를 제거하였습니다.

  • 리뷰 의견을 반영해 코드를 개선했습니다.

테스트 방법

  1. 변경한 코드에 대해 로컬에서 테스트를 진행했습니다.
  2. 멘토님께 CQ 실행을 요청했습니다.

배운 점

  • 코드 리뷰를 통해 구현 방식을 고민하는 경험을 했습니다. 리뷰 의견을 반영하면서 기존 코드와 제안받은 방식의 차이를 살펴보고, 왜 그렇게 수정하는 것이 좋은지 생각해 볼 수 있었습니다. 단순히 코드를 고치는 것을 넘어, 코드의 동작과 의도를 이해하고 공부하는 좋은 기회가 되었습니다.

  • OWNERS를 확인하고 리뷰를 요청하는 방법을 배웠습니다. 디렉터리와 파일마다 담당하는 코드 소유자(OWNER)가 있다는 것을 알게 되었습니다. 수정한 파일의 담당자를 확인하고 리뷰를 요청하는 과정을 통해, 변경 사항을 누구에게 검토받아야 하는지와 리뷰어를 지정하는 방법을 익혔습니다.

  • Gerrit의 패치셋 업데이트 방식을 익혔습니다.
    처음 CL을 올린 뒤 리뷰 의견에 따라 코드를 수정하고 다시 업로드하면, 같은 CL에 새로운 패치셋이 추가되는 과정을 경험했습니다. 이를 통해 하나의 CL에서 수정 이력을 관리하며 리뷰를 이어가는 방식을 이해했습니다.

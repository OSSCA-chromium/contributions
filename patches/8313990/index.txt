<h2 id="문제-설명">문제 설명</h2><p>Chromium에서는 <code>//crypto</code> API를 기능별 하위 네임스페이스로 정리하는<br />마이그레이션이 진행되고 있습니다. 이 과정에서 <code>crypto/sha2.h</code>는 제거될<br />예정이므로, 기존 SHA-256 호출부를 <code>crypto/hash.h</code>가 제공하는 새 API로<br />옮겨야 했습니다.</p>
<p>이번 작업 범위는 <code>components/policy/core/common/cloud</code> 하위 파일입니다.<br />해당 코드들은 component cloud policy 및 external policy data를 캐시에서<br />로드하거나 검증할 때 SHA-256 해시를 사용하고 있었습니다.</p>

<h2 id="배운-점">배운 점</h2><ul>
<li><code>autoninja -C out/Default components_unittests</code>는 테스트 바이너리를 빌드하는<br />단계이고, 실제 테스트 실행은 <code>out/Default/components_unittests --gtest_filter=...</code>로 별도로 수행해야 한다는 점을 확인했습니다.</li>
<li><code>crypto::SHA256HashString()</code>과 <code>crypto::hash::Sha256()</code>는 반환 타입이 다르므로<br />단순 함수명 치환만으로는 기존 raw hash string 동작을 보존할 수 없습니다.</li>
<li>문자열 상수를 새 <code>Sha256()</code> API에 넘길 때는 기존 API와 동일한 입력 범위를<br />유지해야 합니다. 필요하면 <code>std::string_view</code>를 사용해 null terminator가 해시<br />입력에 포함되지 않도록 해야 합니다.</li>
<li>CQ Dry Run은 로컬 빌드보다 넓은 환경에서 테스트를 실행하므로, 로컬에서<br />빌드만 성공한 변경도 실제 테스트 실행 단계에서 동작 차이가 드러날 수<br />있습니다.</li>
</ul>

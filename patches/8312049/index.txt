1a:T16be,<p>WebCrypto의 <code>exportKey()</code>와 <code>wrapKey()</code>가 스펙과 다른 순서로 에러를 검사하던 문제를 고쳤습니다. export를 지원하지 않는 알고리즘의 키에 대해 NotSupportedError 대신 InvalidAccessError를 던지고 있었습니다. 6파일 +118/−8, 새 WPT 1개 추가.</p>
<h2 id="문제-설명">문제 설명</h2><ul>
<li>issue url: <a href="https://crbug.com/41264071">https://crbug.com/41264071</a></li>
<li>스펙은 exportKey 6단계, wrapKey 11단계에서 "키의 알고리즘이 export key 연산을 지원하는지"를 먼저 보고 NotSupportedError를 던집니다. <code>[[extractable]]</code> 검사(InvalidAccessError)는 그다음 단계입니다.</li>
<li>Blink는 앞의 검사를 아예 건너뛰고 있었습니다. 코드에도 <code>TODO(crbug.com/628416)</code>로 순서가 스펙과 다르다는 주석이 남아 있었습니다.</li>
<li>HKDF, PBKDF2 키는 non-extractable로만 import할 수 있어서 두 조건이 항상 동시에 참이고, 그래서 이 순서 차이가 실제로 드러납니다.</li>
</ul>


<h2 id="해결-내용">해결 내용</h2><ol>
<li><code>web_crypto_algorithm.h</code>의 연산 enum에 <code>kWebCryptoOperationExportKey</code>를 추가했습니다.</li>
<li><code>web_crypto_algorithm.cc</code>의 알고리즘 정보 표에 ExportKey 열을 채웠습니다. HKDF, PBKDF2, SHA 계열만 <code>kUndefined</code>(미지원)입니다.</li>
<li><code>subtle_crypto.cc</code>의 <code>exportKey()</code>, <code>wrapKey()</code>에서 extractable 검사보다 먼저 export 지원 여부를 확인하도록 했습니다. 기존 TODO 주석은 지웠습니다.</li>
<li><code>normalize_algorithm.cc</code>에 새 enum 값의 문자열 매핑(<code>"exportKey"</code>)을 추가했습니다.</li>
</ol>
<pre><code class="hljs language-cpp"><span class="hljs-comment">// 14.3.10.6: If the name member of the [[algorithm]] internal slot of key</span>
<span class="hljs-comment">//            does not identify a registered algorithm that supports the</span>

<span class="hljs-addition">+error is: NotSupportedError: Failed to execute 'exportKey' on 'SubtleCrypto': HKDF: Unsupported operation: exportKey</span></code></pre><h3 id="리뷰-과정">리뷰 과정</h3><ul>
<li>dcheng@: wrapKey 쪽 주석에 exportKey가 나오는 게 오타인지 질문 → 오타가 아니라 "exportKey는 항상 지원된다"는 전제가 깨졌기 때문에 wrapKey 쪽 검사도 더는 건너뛸 수 없다는 뜻이라고 답했습니다.</li>
<li>davidben@: <code>supports()</code>의 연산 목록에도 <code>exportKey</code>를 넣어야 하지 않느냐는 지적 → 이 CL은 WPT 하나로 범위를 유지하고, TODO를 남긴 뒤 후속 CL에서 WPT와 함께 처리하기로 합의했습니다.</li>
<li>후속 CL: <a href="https://crrev.com/c/8471207">8471207</a> "[WebCrypto] Fix supports() for exportKey and wrapKey"</li>
</ul>
<h2 id="테스트-방법">테스트 방법</h2><ul>
<li>새 WPT <code>WebCryptoAPI/export-key-error-order.https.any.js</code>를 추가했습니다.<ul>
<li>HKDF, PBKDF2 키로 <code>exportKey()</code>, <code>wrapKey()</code> 호출 시 NotSupportedError</li>
<li>대조군: non-extractable AES-CBC 키는 여전히 InvalidAccessError</li>
</ul>
</li>
<li>수정 코드 없이 테스트만 먼저 올린 패치셋(PS2)에서 새 WPT가 mac-rel에서 실패하는 것을 확인했고, 수정 후 통과했습니다.</li>
<li>수정을 넣은 PS3에서 기존 <code>crypto/subtle/hkdf/exportKey.html</code>이 실패해 PS4에서 기대값을 갱신했습니다.</li>
<li>CQ 통과 후 머지. 추가한 WPT는 upstream으로 자동 export되어 <a href="https://github.com/web-platform-tests/wpt/pull/62737">web-platform-tests/wpt#62737</a>로 머지되었습니다.</li>
</ul>
<h2 id="배운-점">배운 점</h2><ul>
<li>Chromium에서 처음 WPT 관련 이슈를 진행해보면서 새로운 도메인을 익힐 수 있었습니다.</li>
<li>WebCrypto 모듈을 살펴보면서 상당히 복잡하게 구현되어 있어 어려움이 있었지만 AI와 함께 잘 이겨낼 수 있었습니다.</li>
</ul>

[security] Render the SAN with Lit

MERGED2026devtoolsrefactor
2026. 7. 6.parkhojeong
https://crrev.com/c/8045801

SecurityOriginView의 SAN 표시를 Lit으로 전환했습니다. devtools-button에
accessibleExpanded 속성을 추가하고, createSanDiv는 기존 UI와 연결하는 함수로
유지했습니다.

문제 설명

SecurityOriginView는 인증서의 SAN(Subject Alternative Name) 목록을 DOM
생성·수정 코드로 구성하고, 목록을 펼치거나 접을 때 클래스와 버튼 상태를 직접
변경하고 있었습니다. 이 부분을 Lit 템플릿으로 전환하는 작업입니다.

해결 내용

  • renderSan()에서 SAN 항목과 펼치기·접기 버튼을 렌더링하도록 했습니다.
    목록이 비어 있으면 (n/a)를 표시하고, 3개 이하면 모두 표시하며,
    4개 이상이면 처음에는 2개만 표시하는 기존 동작을 유지했습니다.
  • #createSanDiv()에서 접힘 상태를 관리하고, 버튼을 누르면 상태를 바꿔
    다시 렌더링하도록 했습니다. 반환한 요소는 기존 UI에서 사용합니다.
  • 버튼을 devtools-button으로 전환하고, accessibleExpanded 속성으로
    내부 버튼의 aria-expanded를 설정할 수 있도록 했습니다.
  • SAN 표시 테스트 3개와 버튼의 aria-expanded 테스트 2개를 추가하고,
    Security 패널의 빌드 설정에 버튼 컴포넌트 의존성을 추가했습니다.

테스트 방법

SecurityPanel.test.ts에 다음 세 단위 테스트를 추가했습니다.

  • SAN 목록이 비어 있으면 (n/a)를 표시하는지 확인
  • SAN 항목이 3개이면 모두 표시하고 펼치기·접기 버튼은 없는지 확인
  • SAN 항목이 4개이면 처음에는 2개만 표시하고, 버튼을 누를 때 표시 항목,
    버튼 문구, accessibleExpanded 값이 함께 바뀌는지 확인

Button.test.ts에는 accessibleExpanded의 false·true 값이 내부 버튼의
aria-expanded에 반영되고, 속성을 지정하지 않으면 해당 ARIA 속성을
설정하지 않는지 확인하는 테스트 2개를 추가했습니다.

CL 8096246에서 관련 Chromium 웹 테스트의 기대값을 먼저 임시 조정했습니다.
이 CL은 2026년 7월 22일 DevTools main에 병합되었으며, 변경 반영 후
CL 8140384에서 Chromium 쪽 기대 결과를 갱신했습니다.

배운 점

  • 펼치기·접기 UI를 전환할 때는 표시 항목뿐 아니라 버튼 문구와 접근성 상태도
    함께 갱신하고 검증해야 합니다.
  • 리뷰에서 이 변경을 점진적인 전환으로 진행하되, 이후 파일 전체를
    model-view-presenter 구조로 옮기는 방향을 확인했습니다.

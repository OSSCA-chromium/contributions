1a:T2249,<p>Chromium <code>//crypto</code> 라이브러리 API 개편 작업의 일환으로, <code>components/signin</code>에서 사용하던 구형 해시 API(<code>crypto/sha2.h</code>)를 신규 해시 API(<code>crypto/hash.h</code>)로 마이그레이션한 기여입니다.</p>
<h2 id="문제-설명">문제 설명</h2><p><code>crypto/sha2.h</code>의 <code>crypto::SHA256HashString()</code>과 <code>crypto::SHA256Hash()</code>는 <code>crypto</code> 네임스페이스에 바로 놓여 있고, 네이밍도 신규 API 규칙(<code>Sha256</code>, <code>kSha256Size</code>)과 어긋나는 예전 스타일을 따르고 있습니다. <code>//crypto</code> 개편에 따라 해시 API는 <code>crypto::hash</code> 네임스페이스로 옮겨졌고, 각 컴포넌트가 호출부를 신규 API로 옮기는 작업이 필요했습니다.</p>
<p><code>components/signin/</code> 하위에서도 여러 파일이 여전히 구형 API로 SHA-256을 계산하고 있었습니다.</p>
<pre><code class="hljs language-cpp"><span class="hljs-comment">// 구 API (crypto/sha2.h) — 헤더 주석에 이미 deprecated로 표시되어 있습니다.</span>

<h2 id="해결-내용">해결 내용</h2><p><code>components/signin/</code> 하위 파일의 include와 호출부, 상수, 주석을 신규 API 기준으로 정리했습니다.</p>
<ol>
<li>헤더 include 교체: <code>crypto/sha2.h</code> → <code>crypto/hash.h</code> (<code>signin_internals_util.cc</code>는 실제로 해시 API를 쓰지 않는 미사용 include였으므로 대체 없이 제거)</li>
<li>호출부 교체: <code>crypto::SHA256HashString()</code> / <code>crypto::SHA256Hash()</code> → <code>crypto::hash::Sha256()</code></li>
<li>반환 타입 변환: 결과를 문자열로 쓰는 <code>GaiaIdHash::FromGaiaId()</code>, <code>session_binding_utils.cc</code>의 assertion payload 생성 로직 등에서 <code>base::as_string_view()</code>를 거쳐 <code>std::string</code>으로 변환 (<code>Base64UrlEncode()</code>처럼 span을 그대로 받는 호출부는 변환 없이 전달)</li>
<li>상수 교체: <code>crypto::kSHA256Length</code> → <code>crypto::hash::kSha256Size</code> (이 상수를 언급하는 헤더·테스트 주석 포함)</li>
<li><code>git cl format</code>으로 Chromium C++ 스타일에 맞게 줄바꿈 정리</li>

<h2 id="배운-점">배운 점</h2><ul>
<li><strong><code>std::array</code> → <code>string_view</code> → <code>std::string</code> 변환 체인</strong>: <code>crypto::hash::Sha256()</code>이 돌려주는 <code>std::array&lt;uint8_t, 32&gt;</code>를 문자열로 쓰려면 <code>base::as_string_view()</code>를 거쳐야 합니다. 반대로 <code>Base64UrlEncode()</code>처럼 span을 직접 받는 호출부는 변환이 오히려 불필요합니다. 호출부마다 어떤 타입을 요구하는지 확인하고 최소한의 변환만 넣는 것이 중요하다는 것을 배웠습니다.</li>
<li><strong>주석도 마이그레이션 대상</strong>: <code>crypto::kSHA256Length</code>는 코드뿐 아니라 <code>gaia_id_hash.h</code>의 API 설명 주석과 테스트 주석에도 등장했습니다. 상수나 API 이름을 바꿀 때는 이를 언급하는 문서와 주석까지 함께 찾아 고쳐야 리팩토링이 완결된다는 점을 배웠습니다.</li>

FSA: Clean up directory handle context destruction test

MERGED2026blinkfile_system_accesstest
2026. 9. 23.zbnerd
https://crrev.com/c/8452002

디렉터리 핸들의 실행 컨텍스트 파괴를 검증하는 Blink 웹 테스트에서 메서드 목록을 한 줄에 하나씩 배치하여 가독성을 개선했습니다. CL 8434601에서 받은 스타일 리뷰를 반영한 후속 변경입니다.

문제 설명

CL 8434601은 iframe 제거 후 디렉터리 핸들의 네 메서드가 반환하는 예외와 오류 메시지를 검증하는 웹 테스트를 추가했습니다. 해당 테스트는 for...of 구문의 메서드 배열을 한 줄에 나열하고 있었습니다.

리뷰에서 메서드 이름을 각각 별도 줄에 배치하는 선택적 스타일 개선이 제안되었습니다. 당시에는 기존 리뷰 승인을 유지하기 위해 후속 CL에서 정리하기로 했으며, 이 변경에서 해당 제안을 반영했습니다.

해결 내용

수정한 파일은 third_party/blink/web_tests/http/tests/file-system-access/directory-handle-context-destroyed.html입니다. 메서드 배열의 각 항목을 별도 줄로 분리하고 마지막 항목에도 쉼표를 추가했습니다.

-for (const method of
-     ['getFileHandle', 'getDirectoryHandle', 'removeEntry', 'resolve']) {
+for (const method of [
+  'getFileHandle',
+  'getDirectoryHandle',
+  'removeEntry',
+  'resolve',
+]) {

테스트 대상인 getFileHandle(), getDirectoryHandle(), removeEntry(), resolve()와 각 메서드의 검증 조건은 동일합니다. 테스트 로직과 제품 코드는 변경하지 않았습니다.

테스트 방법

  1. 패치 범위 확인

    변경이 for...of 구문의 메서드 배열 서식에만 한정되어 있고, 기존 promise_test 본문과 예외·메시지 검증 코드는 그대로인지 확인했습니다.

  2. 기존 웹 테스트의 검증 내용

    기존 테스트는 iframe에서 OPFS 디렉터리 핸들을 얻은 뒤 iframe을 제거합니다. 이어서 살아 있는 컨텍스트에서 네 메서드를 각각 호출해 InvalidStateError와 실행 컨텍스트 소멸을 설명하는 오류 메시지를 검증합니다. 이번 변경에서는 이 검증을 그대로 유지합니다.

  3. Gerrit CQ 기록 확인

    Patch Set 1은 2026년 9월 23일 16:10 UTC에 CQ dry run을 통과했습니다. 이후 코드 리뷰 승인 두 건과 Commit-Queue +2가 기록되었으며, 18:29 UTC에 full run이 시작되었습니다. 보고서 작성 시점에는 최종 병합 완료 결과가 확인되지 않았습니다.

위 내용은 패치와 Gerrit 기록을 기준으로 정리했으며, 보고서 작성 과정에서 Chromium 웹 테스트를 별도로 실행하지는 않았습니다.

배운 점

  • 테스트 대상 목록을 한 줄에 하나씩 배치하면 각 항목을 읽고 향후 변경 사항을 비교하기 쉽습니다.
  • 리뷰에서는 이런 작은 스타일 변경은 별도 후속 CL보다 원래 CL에 함께 반영하는 편이 낫다는 안내를 받았습니다.
  • 작은 수정으로 리뷰 승인이 초기화되더라도 리뷰어가 기존 검토 내용을 확인하고 다시 승인할 수 있으므로, 승인 유지 자체를 위해 변경을 분리할 필요는 없다는 점을 배웠습니다.

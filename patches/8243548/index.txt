1a:T1e41,<p>Chromium의 <code>components/server_certificate_database</code>에서 deprecated된 <code>crypto/sha2.h</code> 의존성을 제거하고 새로운 <code>crypto/hash.h</code> API로 마이그레이션한 작업입니다.</p>
<h2 id="문제-설명">문제 설명</h2><p>Chromium의 기존 SHA-256 API를 제공하는 <code>crypto/sha2.h</code>는 제거될 예정이며, 호출부를 새로운 <code>crypto/hash.h</code> API로 이전해야 합니다.</p>
<p><code>components/server_certificate_database</code>에서는 다음 두 파일이 <code>crypto/sha2.h</code>를 include하고 있었습니다.</p>
<ul>
<li><code>server_certificate_database.cc</code></li>
<li><code>server_certificate_database_nss_migrator.cc</code></li>
</ul>
<p><code>server_certificate_database.cc</code>에서는 인증서 DER 데이터의 SHA-256 해시를 계산하기 위해 <code>crypto::SHA256Hash()</code>를 사용하고 있었습니다.</p>
<p>반면 <code>server_certificate_database_nss_migrator.cc</code>에서는 <code>crypto/sha2.h</code>를 include하고 있었지만, 실제 SHA-256 API는 사용하지 않고 있었습니다.</p>
<p>주요 문제는 다음과 같습니다.</p>
<ul>
<li>제거 예정인 <code>crypto/sha2.h</code>에 의존하고 있음</li>
<li>기존 <code>crypto::SHA256Hash()</code> API를 사용하고 있음</li>
<li>NSS migrator에 사용되지 않는 SHA-2 헤더가 포함되어 있음</li>
<li>향후 <code>crypto/sha2.h</code> 제거 시 빌드가 실패할 수 있음</li>
</ul>
<p>관련 Chromium 이슈는 <a href="https://crbug.com/372283556">Bug 372283556</a>입니다.</p>
<h2 id="해결-내용">해결 내용</h2><h3 id="1-sha-2-헤더-마이그레이션">1. SHA-2 헤더 마이그레이션</h3><p><code>server_certificate_database.cc</code>의 기존 헤더를 새로운 hash API 헤더로 교체했습니다.</p>
<pre><code class="hljs language-diff"><span class="hljs-deletion">-#include "crypto/sha2.h"</span>
<span class="hljs-addition">+#include "crypto/hash.h"</span></code></pre><h3 id="2-sha-256-함수-마이그레이션">2. SHA-256 함수 마이그레이션</h3><p>인증서 DER 데이터의 SHA-256 해시를 생성하는 기존 호출을 새로운 API로 변경했습니다.</p>
<pre><code class="hljs language-diff"><span class="hljs-deletion">-sha256hash_hex = base::HexEncodeLower(crypto::SHA256Hash(cert));</span>
<span class="hljs-addition">+sha256hash_hex = base::HexEncodeLower(crypto::hash::Sha256(cert));</span></code></pre><p>기존 코드와 변경된 코드 모두 다음 작업을 수행합니다.</p>
<ol>
<li>인증서 DER 데이터의 SHA-256 해시 계산</li>
<li>32바이트 해시 결과 생성</li>
<li>해시 결과를 소문자 hexadecimal 문자열로 변환</li>
<li>데이터베이스의 <code>sha256hash_hex</code> 값으로 저장</li>
</ol>
<p>따라서 저장되는 해시 값과 데이터베이스 형식에는 변화가 없습니다.</p>
<h3 id="3-사용되지-않는-헤더-제거">3. 사용되지 않는 헤더 제거</h3><p><code>server_certificate_database_nss_migrator.cc</code>에서는 SHA-2 API를 직접 사용하지 않으므로 기존 헤더를 제거했습니다.</p>
<pre><code class="hljs language-diff"><span class="hljs-deletion">-#include "crypto/sha2.h"</span></code></pre><p>초기 patchset에서는 이를 <code>crypto/hash.h</code>로 교체했지만, 해당 파일에서 hash API를 사용하지 않는다는 리뷰 피드백을 받았습니다.</p>
<p>피드백을 반영하여 불필요한 <code>crypto/hash.h</code>도 제거하고, 해당 파일에는 crypto hash 관련 헤더가 남지 않도록 수정했습니다.</p>
<h3 id="4-최종-변경-파일">4. 최종 변경 파일</h3><ul>
<li><code>components/server_certificate_database/server_certificate_database.cc</code></li>
<li><code>components/server_certificate_database/server_certificate_database_nss_migrator.cc</code></li>
</ul>
<p>최종 변경 규모는 다음과 같습니다.</p>
<pre><code class="hljs language-text">2 files changed, 2 insertions(+), 3 deletions(-)</code></pre><p>테스트 파일이나 <code>BUILD.gn</code> 파일은 변경하지 않았습니다.</p>
<h2 id="테스트-방법">테스트 방법</h2><h3 id="1-관련-빌드-타깃-확인">1. 관련 빌드 타깃 확인</h3><p>다음 명령어로 <code>server_certificate_database</code> 관련 타깃이 정상적으로 컴파일되는지 확인했습니다.</p>
<pre><code class="hljs language-bash">autoninja -C out/Default components/server_certificate_database:unit_tests</code></pre><p>빌드는 성공적으로 완료되었습니다.</p>
<p>현재 사용한 <code>out/Default</code> 설정은 Linux 빌드이므로, <code>is_chromeos</code> 조건부 소스인 <code>server_certificate_database_nss_migrator.cc</code>는 이 빌드에서 직접 컴파일되지 않습니다.</p>
<h3 id="2-deprecated-api-잔존-검사">2. Deprecated API 잔존 검사</h3><p>대상 디렉터리에 기존 SHA-2 헤더와 API가 남아 있지 않은지 확인했습니다.</p>
<p>확인 항목은 다음과 같습니다.</p>
<ul>
<li><code>crypto/sha2.h</code> include가 남아 있지 않음</li>
<li><code>crypto::SHA256Hash()</code> 호출이 남아 있지 않음</li>
<li><code>server_certificate_database.cc</code>에서 <code>crypto/hash.h</code> 사용</li>
<li><code>crypto::hash::Sha256()</code> 호출 사용</li>
<li>NSS migrator에 불필요한 hash 관련 헤더가 없음</li>
</ul>

<pre><code class="hljs language-bash">git diff --check</code></pre><p>검사를 통과했습니다.</p>
<h3 id="4-gerrit-presubmit">4. Gerrit Presubmit</h3><p>새 patchset 업로드 과정에서 Gerrit upload presubmit을 실행했습니다.</p>
<pre><code class="hljs language-text">0 Presubmit Messages
0 Presubmit Warnings

<h2 id="배운-점">배운 점</h2><ul>
<li>Deprecated API 마이그레이션에서는 헤더 이름을 기계적으로 교체하기보다 각 파일이 해당 API를 실제 사용하는지 확인해야 합니다.</li>
<li>기존 헤더의 심볼을 사용하지 않는 파일에서는 새로운 헤더로 교체하는 대신 include를 완전히 제거하는 것이 적절합니다.</li>
<li><code>crypto::SHA256Hash()</code>와 <code>crypto::hash::Sha256()</code>는 모두 고정 크기 SHA-256 결과를 제공하므로 기존 <code>base::HexEncodeLower()</code> 호출 구조를 유지할 수 있습니다.</li>
<li>public API나 데이터베이스 형식을 변경하지 않고 내부 crypto 의존성만 안전하게 교체할 수 있었습니다.</li>
<li>Gerrit 리뷰 피드백을 반영할 때는 실제 심볼 사용 여부를 다시 검색하고 최소한의 변경만 유지하는 것이 중요합니다.</li>
<li>별도의 테스트 코드를 추가하지 않고 기존 관련 타깃 빌드와 presubmit으로 마이그레이션을 검증했습니다.</li>
</ul>

[security] Migrate SecurityOriginView certificate section to Lit

MERGED2026devtoolsrefactor
2026. 8. 31.parkhojeong
https://crrev.com/c/8324787

SecurityOriginView의 certificate section을 Lit으로 전환했습니다. certificate details 표시와
certificate viewer를 여는 동작의 테스트를 추가했습니다.

문제 설명

certificate section은 기존 DOM 생성 코드로 구성하고, SAN 목록만 별도로 Lit으로
렌더링하고 있었습니다. 인증서 정보와 SAN, 상세 보기 버튼을 하나의 Lit
렌더링 흐름으로 전환하는 작업입니다.

해결 내용

  • buildCertificateDetailsRows()와 renderCertificateSection()에서 인증서
    제목과 상세 정보 표를 만들도록 했습니다. Subject, SAN, 유효 기간, Issuer,
    상세 보기 버튼의 순서와 제목의 접근성 속성을 유지했습니다.
  • 표의 값에 문자열뿐 아니라 Lit 템플릿도 사용할 수 있도록 확장하고,
    SAN과 상세 보기 버튼을 템플릿으로 포함했습니다.
  • #createCertificateSection()에서 SAN의 접힘 상태를 관리하고, 버튼 클릭 시
    certificate section을 다시 렌더링하도록 했습니다. 기존 #createSanDiv()는 제거했습니다.
  • 인증서 조회와 뷰어 호출을 #showCertificateViewer로 옮겼습니다.
    조회 결과가 비어 있으면 뷰어를 호출하지 않는 동작을 유지했습니다.
  • certificate section의 단위 테스트 5개와 테스트에 필요한 Host 의존성을 추가했습니다.

테스트 방법

SecurityPanel.test.ts에 다음 다섯 단위 테스트를 추가했습니다.

  • 제목과 role="heading", aria-level="2" 확인
  • security details가 없을 때 certificate section 생략
  • 인증서 정보의 표시 순서와 유효 기간의 UTC 문자열 확인
  • 상세 보기 버튼 클릭 후 Origin으로 인증서를 조회하고 결과를 뷰어에 전달하는지 확인
  • 조회 결과가 빈 배열이면 비동기 조회 완료 후에도 뷰어를 호출하지 않는지 확인

리뷰 중 Chromium 보안 웹 테스트 2개의 실패가 보고되어, CL 8398154에서
기대값을 임시 조정했습니다. 이후 CQ 실행이 통과했으며,
2026년 9월 14일(한국 시간) DevTools main에 병합되었습니다.

배운 점

  • 일부만 Lit으로 전환된 영역을 통합할 때는 기존 상태 관리와 클릭 동작도
    새 렌더링 흐름에 연결해야 합니다.
  • 비동기 동작이 발생하지 않는 경우를 검증할 때도 선행 비동기 작업이 끝난 뒤
    호출 여부를 확인해야 합니다.

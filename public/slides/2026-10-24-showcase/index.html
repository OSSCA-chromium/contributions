사례 1 · 공통 마이그레이션

대표 CL 8148099 · safe_browsing/db: migrate to crypto/hash APIs — 최민섭

  • 문제

    //crypto가 crypto/sha2.h를 없애고 crypto/hash.h로 옮기는 중. 사용처가 여러 디렉터리에 흩어져 있어 나눠서 진행하기 좋은 작업

  • 해결

    Safe Browsing DB의 해시 계산을 새 API로 교체. 반환 타입이 문자열에서 바이트 배열로 바뀌어, 문자열이 필요한 호출부에는 변환을 추가

  • 팀으로 확장

    이슈 진행자의 동의를 얻어 팀 레포 이슈 #282로 공유하고, 디렉터리별 sub-issue를 선착순으로 나눠 멘티들의 첫 코드 기여로 연결

사례 2 · viz 코드 정리

대표 CL 8348446 · [viz] Remove Capabilities::supports_surfaceless — 김범수

  • 문제

    같은 사실을 서로 다른 계층의 이름으로 말하는 플래그가 두 개. supports_surfaceless는 이름과 달리 GPU 능력을 조회하지 않았고, 2019년 TODO와 함께 죽은 코드도 남아 있었음

  • 해결

    플래그를 읽는 여섯 곳이 모두 두 값이 같은 플랫폼에서만 실행됨을 확인한 뒤 renderer_allocates_images로 통일

  • 이어진 작업

    viz 구조를 10주차 모임에서 발표하고, swap 실패 시 표시 중인 오버레이가 해제되던 버그 수정으로 확장 (CL 8448731, 리뷰 중)

6곳플래그 사용처를 따라가며 확인
2019년부터 남아 있던 TODO 정리
9/11병합 · 9/19 팀 발표

사례 3 · WPT로 찾은 웹 표준 버그

대표 CL 8311028 · [Blink] Fix capitalization after supplementary characters — 박호정

  • 문제

    text-transform: capitalize가 이모지 같은 보충 평면 문자 뒤의 단어 경계를 잘못 판단해, css-pseudo의 WPT가 Chromium에서 실패

  • 해결

    이전 문자를 UTF-16 코드 유닛 하나로 넘기던 것을 코드 포인트 단위로 바꾸고, 회귀 테스트를 추가한 뒤 WPT 실패 기대값을 제거

  • 리뷰에서 배운 점

    동작 변경은 런타임 플래그 뒤에 두어 문제가 생기면 되돌릴 수 있게 함. 리뷰 코멘트 대응 과정은 9주차 모임에서 발표

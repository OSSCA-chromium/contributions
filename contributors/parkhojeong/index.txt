HTML 스펙에 따르면 `in head noscript` insertion mode에서는 `head`와 `noscript`
시작 태그를 무시해야 합니다. 기존에는 이 모드에서 `head` 시작 태그를 만나면 잘못해서
`in head` 모드로 전환했습니다. `head` 시작 태그를 무시하도록 수정했습니다.

변경은 기본 활성화된 runtime flag로 제어하며, 필요하면 flag를 비활성화해
기존 동작으로 되돌릴 수 있습니다.

## 문제 설명

scripting이 비활성화된 상태에서 `<head><noscript><head><style></style>`을 파싱하면,
중첩된 `<head>` 때문에 `in head noscript` 모드를 벗어나 이후 `<style>`이
`<noscript>`의 자식으로 생성되지 않았습니다. 이로 인해
`inhead-noscript-head.html` WPT가 실패했습니다.

## 해결 내용

- `HTMLTreeBuilder::ProcessStartTag()`의 `kInHeadNoscriptMode` 처리에
  `HTMLTag::kHead` 분기를 추가했습니다.
- 해당 시작 태그를 parse error로 처리하고 반환해, insertion mode를 유지한 채
  태그를 무시하도록 했습니다.
- `HTMLParserIgnoreHeadInNoscript`를 `stable` 상태의 runtime flag로 추가했습니다.
  flag가 꺼져 있으면 기존 처리 경로를 따릅니다.
- 해당 WPT의 실패 기대 결과 파일을 제거했습니다.

## 테스트 방법

CL에 기록한 검증 대상은 다음 WPT입니다.

- `external/wpt/html/syntax/parsing/inhead-noscript-head.html`

이 테스트는 scripting이 비활성화된 iframe에서 중첩된 `<head>`를 파싱한 뒤,
`<noscript>`의 첫 자식이 `HTMLStyleElement`인지 확인합니다.

CQ를 통해 2026년 10월 1일(한국 시간) Chromium main에 병합되었습니다.

## 배운 점

- HTML parser는 잘못된 태그를 만났을 때도 스펙에 정해진 오류 처리와 insertion mode를
  따라야 이후 DOM을 올바르게 구성할 수 있습니다.
- 기본 활성화된 runtime flag를 두면, 문제가 발견됐을 때 flag를 비활성화해
  기존 파싱 동작으로 되돌릴 수 있습니다.

## 문제 설명

`Certificate Transparency section`은 SCT 요약·상세 정보와 CT compliance 안내 문구를 DOM 생성 코드로

이 영역을 Lit 템플릿과 표시 상태에 따라 렌더링하도록 전환하는 작업입니다.

## 해결 내용

- SCT 요약, 상세 정보, CT compliance 안내 문구를 각각 Lit 템플릿으로 만들고,
  `renderCertificateTransparencySection()`에서 함께 렌더링하도록 했습니다.
- `#createCertificateTransparencySection()`에서 상세 표시 상태를 관리하고,
  클릭 시 요약·상세 정보의 표시와 버튼 문구·접근성 속성을 함께 갱신합니다.
- SCT가 없고 CT compliance가 `Unknown`이면 영역을 생략하는 기존 조건을 유지했습니다.
  CT compliance가 `Unknown`인 경우 안내 문구도 표시하지 않습니다.
- `renderDetailsTable()`에 추가 클래스를 전달할 수 있도록 확장하고,
  더 이상 사용하지 않는 `SecurityDetailsTable` 클래스를 제거했습니다.

## 문제 설명

`HarfBuzzShaper`는 8비트 문자열에 대해 문자 방향에 따른 구간 분할을 생략합니다.
따라서 8비트로 저장된 사용자 지정 하이픈 문자열 `+=`는 세로쓰기의
`text-orientation: mixed`에서도 올바른 회전이 적용되지 않았습니다.

이로 인해 `css/css-text/hyphens/hyphens-vertical-003.html` WPT가 실패했습니다.

## 해결 내용

- `HyphenResult::Shape()`에서 글꼴 방향이 `kVerticalMixed`인 경우
  `text_.Ensure16Bit()`를 호출하여 하이픈 문자열을 16비트로 저장하도록 했습니다.
  이를 통해 shaper가 문자 방향 처리를 적용할 수 있도록 했습니다.
- 기본 활성화된 `HyphenVerticalOrientationFix` 런타임 플래그를 추가하여,
  필요할 때 플래그를 비활성화하면 기존 동작으로 돌아갈 수 있도록 했습니다.
- 가로쓰기, 세로쓰기의 `upright`와 `mixed`를 검증하는 단위 테스트를 추가하고,
  해당 WPT의 실패 기대값을 제거했습니다.

## 테스트 방법

가로쓰기와 세로쓰기 `upright`의 기존 동작을 유지하면서, 세로쓰기 `mixed`에서는

## 배운 점

- 같은 문자열이라도 내부 저장 방식이 8비트인지 16비트인지에 따라 shaper의
  처리 경로가 달라질 수 있으므로, 렌더링 문제를 분석할 때 저장 방식도 확인해야 합니다.
- 수정 대상인 세로쓰기 `mixed`뿐 아니라 가로쓰기와 `upright`도 함께 검증해야
  다른 쓰기 방향에 회귀 문제가 생기지 않는지 확인할 수 있습니다.
- 런타임 플래그로 변경 동작을 제어하면 문제가 발생했을 때 기존 동작으로 빠르게
  되돌릴 수 있으며, 플래그를 켠 경우와 끈 경우 모두 테스트해야 합니다.

## 문제 설명

`base/files/file_path_watcher_unittest.cc`의
`FilePathWatcherTest.NonExistentDirectory`는 부모 디렉터리와 파일이 모두 없는

감시 대상은 파일이므로 부모 디렉터리만 생성하는 단계에서는 이벤트가 발생하지

## 해결 내용

부모 디렉터리를 생성한 직후의 TODO를 `delegate.SpinAndExpectNoEvents()`
호출로 교체했습니다.

```diff
 ASSERT_TRUE(CreateDirectory(dir));
-// TODO(crbug.com/40263777): Expect that no events are fired.
+delegate.SpinAndExpectNoEvents();
```

이 helper는 이벤트 루프를 잠시 실행하여 비동기 알림이 처리될 시간을 준 뒤,
수신한 이벤트 목록이 비어 있는지 확인합니다. 이어지는 파일 생성, 수정, 삭제
이벤트 검증은 유지했습니다.

리뷰에서는 TODO가 추가될 당시에는 `SpinAndExpectNoEvents()`가 없었다는
배경을 확인했습니다. 또한 리뷰 의견에 따라 커밋 메시지에 기존 TODO를 해결하고
이 helper로 기대 동작을 검증한다는 설명을 추가했습니다.

## 배운 점

- 파일 감시 알림은 비동기로 전달되므로, 디렉터리 생성 직후에는 잘못된 이벤트도
  아직 도착하지 않았을 수 있습니다. 이벤트 루프를 잠시 실행한 뒤 수신 목록이

## 문제 설명

`FilePathWatcherTest.WatchDirectory`는 Apple에서 파일 수정 단계를 건너뛰고,
이벤트가 발생하지 않는지 확인하라는 TODO만 남겨 두었습니다.

이 테스트에서 사용하는 Apple의 비재귀 감시(`kNonRecursive`)는
`kqueue`로 디렉터리 경로를 감시하며, 내부 파일은 개별 감시하지 않습니다.
파일 생성·삭제는 디렉터리의 항목 목록을 바꾸므로 감지됩니다.
반면 기존 파일의 내용만 수정하면 항목 목록은 그대로이므로,
이 감시 방식에서는 이벤트가 보고되지 않습니다.

## 해결 내용

루프를 잠시 실행한 뒤, 수신 목록이 기존 기대 목록과 일치하는지 확인합니다.

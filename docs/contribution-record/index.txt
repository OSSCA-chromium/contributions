<h2 id="0-gerrit-기본-설정-새-cl을-work-in-progress로-최초-1회">0. Gerrit 기본 설정 — 새 CL을 Work in Progress로 (최초 1회)</h2><p><a href="https://chromium-review.googlesource.com/settings/">Gerrit 설정</a>의 Preferences에서<br /><strong>Set new changes to "work in progress" by default</strong>를 체크하세요.</p>
<ul>
<li>체크해 두면 <code>git cl upload</code>로 올린 CL이 리뷰어에게 바로 노출되지 않는<br />WIP(Work in Progress) 상태로 만들어집니다.</li>
<li>멘토에게 커밋 메시지와 변경 내용을 확인받은 뒤, Gerrit 화면에서<br /><strong>Start Review</strong>를 눌러 리뷰를 시작합니다.</li>
</ul>
<h2 id="1-기록-파일-만들기">1. 기록 파일 만들기</h2><p><code>data/contributions/template.md</code>를 <code>{ChromiumReviewId}.md</code>로 복사합니다.</p>
<pre><code class="hljs language-bash"><span class="hljs-built_in">cp</span> data/contributions/template.md data/contributions/6520751.md</code></pre><p><code>ChromiumReviewId</code>는 Gerrit URL의 마지막 숫자입니다.<br />예: <code>https://chromium-review.googlesource.com/c/chromium/src/+/6520751</code> → <code>6520751.md</code></p>

<ul>
<li><code>date</code>는 반드시 유효한 <code>YYYY-MM-DD</code> 형식이어야 합니다. 잘못된 날짜(예:<br /><code>2025-05-D8</code>)는 CI에서 걸리고, 통과하더라도 목록 정렬을 조용히 깨뜨립니다.</li>
<li><code>author</code>는 기여자 페이지 링크와 아바타에 그대로 사용되므로 정확한 GitHub<br />ID를 적으세요.</li>
<li><strong>템플릿의 안내 주석(<code># github.com/GitHubId</code>, <code># Add XXXXX from ...</code> 등)은<br />모두 지우세요.</strong></li>
</ul>
<h3 id="본문-작성">본문 작성</h3><ul>
<li>문제 설명 / 해결 내용 / 테스트 방법 / 배운 점 / 참고 자료 — 각 섹션의 안내<br />문구를 실제 내용으로 교체합니다.</li>
<li>해당 사항이 없는 섹션(예: 문서 수정이라 테스트가 없는 경우)은 제거해도<br />됩니다.</li>
<li>템플릿에 있는 <code>https://example.com</code> 같은 placeholder 링크는 반드시<br />제거하세요.</li>
</ul>
<h2 id="2-로컬-검증">2. 로컬 검증</h2><p>PR을 올리기 전에 CI 검사 중 데이터 관련 두 가지를 로컬에서 돌려봅니다.<br />(CI는 이 외에 테스트·ESLint·빌드도 실행하지만, <code>data/contributions/</code>만<br />추가했다면 아래 두 가지가 통과하면 충분합니다.)</p>
<pre><code class="hljs language-bash">npm run validate:data   <span class="hljs-comment"># frontmatter 검사</span>
npm run lint:md         <span class="hljs-comment"># 마크다운 린트</span></code></pre><p>렌더링을 직접 확인하려면 <code>npm run dev</code> 실행 후<br /><code>http://localhost:3000/contributions/patches/</code>에서 본인 항목을 열어보세요.</p>
<h2 id="3-pr-올리기">3. PR 올리기</h2><pre><code class="hljs language-bash">git checkout -b 250725-contribution-6520751   <span class="hljs-comment"># 브랜치명: YYMMDD-주제</span>
git add data/contributions/6520751.md
git commit -m <span class="hljs-string">"contributions: Add 6520751"</span>
git push origin 250725-contribution-6520751</code></pre><ul>
<li>커밋 메시지: <code>data/contributions/</code> 변경은 <strong><code>contributions:</code> prefix</strong>를<br />사용합니다. 제목은 현재형 동사로 시작, 첫 글자 대문자, 마침표 없음.</li>
<li>push 후 GitHub에서 본인 fork 페이지에 뜨는 <strong>Compare &amp; pull request</strong><br />버튼을 누르거나, fork의 해당 브랜치에서 <strong>Contribute → Open pull<br />request</strong>로 PR을 생성합니다.</li>
<li>base가 <code>OSSCA-chromium/contributions</code>의 <code>main</code>인지 확인하세요 (본인 fork의<br /><code>main</code>이 아닙니다).</li>
<li>CI(테스트·린트·데이터 검증)가 통과하는지 확인하고, 실패하면 로그를 보고<br />수정 커밋을 추가합니다.</li>
<li>PR이 merge되면 사이트에 자동 배포됩니다(수 분 소요).</li>
</ul>
<h2 id="4-cl이-merge되면-status-갱신">4. CL이 merge되면 — status 갱신</h2><p>Gerrit에서 CL이 최종 merge되면, 후속 PR로 <code>status</code>만 갱신합니다.</p>
<pre><code class="hljs language-bash">git checkout main &amp;&amp; git pull
git checkout -b 250801-merged-6520751</code></pre><p><code>data/contributions/6520751.md</code>의 frontmatter에서 <code>status: in review</code>를<br /><code>status: merged</code>로 수정한 뒤, 같은 방식으로 커밋·push·PR을 올립니다.</p>
<pre><code class="hljs language-bash">git commit -am <span class="hljs-string">"contributions: Mark 6520751 as merged"</span>
git push origin 250801-merged-6520751</code></pre><h2 id="5-github-이슈프로젝트-보드">5. GitHub 이슈·프로젝트 보드</h2><ul>
<li>실습 이슈는 오른쪽 <strong>Assignees</strong>에 본인을 직접 지정(self-assign)해<br />시작합니다 (이슈당 1인, 선착순).</li>
<li>담당한 GitHub 이슈에 <strong>Gerrit CL 링크</strong>와 <strong>기여 기록 PR 링크</strong>를 코멘트로<br />남기세요.</li>
<li>진행 상태에 따라 프로젝트 보드(2026 Chromium Issues)의 <strong>Status</strong>를 직접<br />변경하세요: <code>멘티 작업 진행 중</code> → <code>멘토 리뷰 중</code> → <code>gerrit 리뷰 중</code> →<br /><code>반영 완료</code>.</li>
<li>이슈 close는 멘토가 처리합니다.</li>
</ul>
<h2 id="자주-하는-실수">자주 하는 실수</h2><p>작년(2025) 기록에서 실제로 반복됐던 실수들입니다.</p>
<ol>
<li><strong>템플릿 주석 잔재</strong> — <code>author: ppirabbang # github.com/GitHubId</code>처럼<br />안내 주석을 지우지 않고 제출.</li>
<li><strong>placeholder 링크 방치</strong> — 참고 자료에<br /><code>[관련 문서 링크](https://example.com)</code>가 그대로 남음.</li>
<li><strong>섹션 내용 뒤바뀜</strong> — "테스트 방법" 섹션에 배운 점을 작성하는 등 안내<br />문구와 내용이 어긋남.</li>
<li><strong>status 미갱신</strong> — CL은 merge됐는데 기록은 계속 <code>in review</code>로 남아 통계가<br />틀어짐.</li>
<li><strong>커밋 메시지 형식</strong> — <code>Create 6619930.md</code>, <code>Update 6508290.md</code> 같은 기본<br />메시지 사용. <code>contributions: Add 6619930</code> 형식을 지켜주세요.</li>
</ol>
